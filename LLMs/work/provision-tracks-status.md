# LLMs 提供トラック別ステータス管理

本リポジトリ（A = cc-relative-info）および兄弟リポジトリ（B = empty-can/LLMs）が提供する llms.txt 系コンテンツを、**2 つの提供トラック**に分けて整備状況を管理する。最終アウトプット形式（`llms.txt` / `llms-full.txt`）は揃えるが、**実施すべき整備・公開パス・取得方式・運用が異なる**ため、user-review の確認事項 Q1〜Q6 とバックログ B-1〜B-13 をトラック別に仕分ける。

> 従来これらは「本リポジトリが提供する llms.txt」として一括管理されており、official-docs と gen-out の観点が混在していた。本ファイルはその分離管理の単一情報源。gen-out トラックの活動詳細は `user-review/_progress.md`、official-docs パイプラインの設計は `publish-migration/migration-plan.md` を参照。

作成: 2026-06-06

## トラック定義

| トラック | 対象 | リポジトリ / 公開パス | 鮮度 | 取得方式 | 現フェーズ |
|---|---|---|---|---|---|
| **official-docs** | 各公式団体が公開する llms.txt の取り込み＋更新サマリ | **B = empty-can/LLMs（公開済み）**。`official-llms-txts/` / `official-doc-update-summary/` | F1 のみ（最新追随） | dl（ダウンロード） | **公開・日次運用中** |
| **gen-out**（generated） | llms.txt 非提供のリポジトリから生成した llms.txt（47 ターゲット） | **A = cc-relative-info**（`LLMs/work/gen-out/`、未公開）。将来 B へ `generated-*` で公開予定 | F1 中核 ＋ F2 論点 | gen（生成） | **P0 設計段階** |
| **共通基盤** | 両トラックにまたがる横断観点（用語・CLAUDE.md 原則・発見経路） | A 側に集約（メタ開発資産） | — | — | 一部実施済み |

**核心の差**: official-docs は「対象 2 つ（Claude Code docs / MCP）・F1 のみ・dl ベース」。gen-out は「対象 47・F1/F2・生成 narrative ベース」。**多数リポの生成管理・版固定・narrative 品質に関する観点は gen-out 固有**であり official-docs には発生しない。

## official-docs トラックで「実施不要」な観点（明示）

ユーザー指摘の「official-docs では実施不要な整理観点」を確定列挙する。いずれも **多数リポの生成管理・版固定・生成 narrative 品質**に固有で、対象固定・F1 のみ・dl ベースの official-docs には構造的に発生しない:

- **Q2 / B-3**（F2 版固定）— official-docs は最新追随のみ
- **B-7 / B-8 / B-9**（アクティビティ階層・タグ・リリース検知）— 対象が 2 サイト固定
- **B-10 / B-11 / B-12**（narrative キーワード網羅性・安定化・辞書タグ）— official-docs は dl した原文ベースで narrative 生成の揺らぎ問題が無い
- **B-13**（リポジトリ単位生成ルール）— 生成しないため不要
- **Q1 / Q6**（シナリオ数確定・レビュー方法）— 既に公開・運用フェーズで、レビュー設計の確定対象ではない
- **Q4**（命名）— glossary 用語が利用者向け公開物（README・サマリ）に未使用と Grep で実証済。確定が遅れても official-docs に実害なし（共通基盤として名目上のみ残る）

## 各トラックの現ステータスサマリ

### official-docs（B、公開・運用中）

- **実施済み**: B への移行・公開（B-2）、日次スケジューラ（B-6）、CLAUDE.md 配置原則の構造適用（Q5/B-1 の B 側）、Phase 3 第三者レビュー、footer 再ベース
- **残**: Phase 5（A クリーンアップ、2026-06-07 の初回実行確認後）、B-4（発見経路）、実運用の品質観察
- **不要**: 上記「実施不要な観点」セクション参照

### gen-out（A、P0 設計段階）

- **現フェーズ**: P0.1 round 2 完了・最終確定据え置き・P0.2 以降未着手（詳細は `user-review/_progress.md`）
- **残（レビュー設計）**: Q1 / Q2 / Q3 / Q6、P0.2〜P4
- **残（運用自動化）**: B-2（B 公開）/ B-3（F2）/ B-5 / B-6（日次化）/ B-7 / B-8 / B-9
- **残（narrative 品質）**: B-10 / B-11 / B-12（B-12 が B-10/11 を置換しうる）
- **残（生成ルール）**: B-13

### 共通基盤

- **Q4**（glossary 命名）: official-docs の利用者向け公開物には未使用（Grep 実証）＝official-docs では実質不要。**確定すれば両トラックに同一適用され、トラック間で差異は出ない**
- **Q5 / B-1**（CLAUDE.md 原則）: B は実施済み、**A 側の明文化が残**＝公開を機に前進する候補
- **B-4**（発見経路）: 同一リポジトリ B の発見経路で整備手段も共通。**トラック間で整備内容の差異は出ない**（official-docs 公開済みで顕在・gen-out 公開時に顕在という時期のズレは観点差ではなく、official-docs で設計すれば gen-out へ流用できる共通資産）

> **Q4・B-4 の確定整理（2026-06-06）**: 両者は共通基盤の観点で、トラック間で整備内容が分岐しない。official-docs トラックで「不要・実施済み・運用観察・優先度低」以外に能動的に残るのは**実質 B-4（発見経路）のほぼ 1 点**。
