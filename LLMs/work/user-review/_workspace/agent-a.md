## 注記・気付き

1. **E2 での発見経路の問題**: E2 シナリオの多くは「本リポジトリの llms.txt の URL / パスをどうやって知るか・どうやって渡すか」という共通の課題を持つ。CLAUDE.md への記述（S-A7）や README への掲載が解決策の候補

2. **H/P の境界ケース**: S-A5、S-A11、S-A14 のように「人が起点だがファイル取得・参照は自動化または Claude が行う」シナリオが複数ある。軸 1 の H/P は純粋な二分ではなく、「起点」と「運用」を分けて考える必要があるかもしれない

3. **llms.txt と llms-full.txt の役割分担**: E3 シナリオでは llms-full.txt の全文取り込み価値が高く、E2 シナリオでは llms.txt の索引ナビゲーション機能が重要になる傾向がある

4. **F2 ニーズは存在するが提供側の対応が必要**: S-A4、S-A12 は F2（版固定）の具体的なニーズを示しているが、本リポジトリが実際に F2 snapshot を提供しているかは確認していない（参照禁止ファイル群のため）。F2 を充足するには別途アーカイブ戦略が必要

5. **非エンジニア利用者（S-A13）**: テックライター（S-A15）と合わせ、llms.txt の記述スタイルが非技術者にも有用かどうかという新たな評価軸が生まれた

6. **コレクション性の活用（S-A6）**: 複数リポジトリの llms.txt が同フォーマットで揃うことで横断比較が可能になる。単一リポジトリの llms.txt 提供者にはない本リポジトリ固有の価値

## glossary-proposal

### インライン参照 (inline reference)
- 提案理由: S-A7 において「CLAUDE.md に llms.txt の URL を記述し Claude Code が自動参照する」という構造を説明したが、「CLAUDE.md 経由での間接参照」を表す用語がなく説明が冗長になった
- 暫定定義: CLAUDE.md や設定ファイルに llms.txt / llms-full.txt の URL またはパスを記述することで、Claude Code セッション開始時または指示実行時に自動的に参照される状態。人が個別に指示せずとも参照が発動する仕組み
- 適用範囲: E2 シナリオにおける「人が設定→Claude が自律参照」のパターンを記述するとき

### 全文取り込み (full-text ingest)
- 提案理由: S-A3・S-A5・S-A14 において「llms-full.txt のテキストをコンテキストまたは RAG に丸ごと入れる」行為を繰り返し記述した。「参照」とも「索引利用」とも異なるニュアンス（URL を辿らず全文を直接処理対象にする）を持つ
- 暫定定義: `llms-full.txt` のテキスト全体を、URLクロールなしに直接コンテキスト・ベクトル DB・プロンプトに組み込む行為。「取り込み (ingest)」の特殊形で、索引ナビゲーションを経ずに全文を対象とする点が特徴
- 適用範囲: E3 でのコンテキスト補強シナリオ、RAG データソース登録シナリオを記述するとき
