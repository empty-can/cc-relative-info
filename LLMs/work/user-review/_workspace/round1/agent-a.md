- **注記**: Claude Code が CLAUDE.md や `.claude/` の設定で本リポジトリの `llms.txt` を context に組み込んでいる場合は完全に E2。組み込みがなく手動で URL 貼りつけの場合は E3 寄り

## 注記・気付き

1. **発見性の問題**: 多くのシナリオで「どうやって本リポジトリの llms.txt を知るか」が前提として問われていない。実際の利用には「存在を知っている」か「Claude が自律的に参照する仕組みがある」かが必要。この前提条件はシナリオ評価に影響する

2. **鮮度の問題**: S-A8 で特に顕著だが、llms.txt が生成された時点からライブラリが更新された場合、索引が古くなる。鮮度に依存するシナリオと依存しないシナリオを区別しておくべき

3. **E2/E3 の境界**: Claude Code のコンテキストに自動でロードされるか、ユーザーが手動で URL を渡すかで E2/E3 が変わる。「Claude Code の CLAUDE.md 設定で本リポジトリが参照されている」かどうかが境界になる

4. **sub-agent 境界**: S-A5 のようにスクリプトから API を叩くケースは、人が書いたスクリプトの実行を「H」と見なすか「P」と見なすかが曖昧。「人がインタラクティブに指示を出している」ならば H と判断した

5. **cc-extensions vs 個別 llms.txt**: cc-extensions メタインデックスと個別リポジトリの llms.txt は用途が異なる。前者は「Claude Code 拡張の横断索引」、後者は「特定 OSS の API 索引」。この違いはシナリオ分類に影響する

6. **「索引のコレクション」としての価値**: 本リポジトリは 47 リポジトリ分をまとめて提供する点に独自価値がある。この「コレクション性」を活かすシナリオ（S-A5, S-A9, S-A12）は特に注目

7. **メンテナー除外との境界**: S-A6（自分の別 OSS に generate-llms-txt を導入する）はメンテナー除外に近いが、「本リポジトリ自身の整備」ではなく「別リポジトリへの導入」なので含めた。後段で要検討
