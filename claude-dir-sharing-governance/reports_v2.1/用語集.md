# 用語集

版: v0.1（改訂履歴は [用語集【別紙】改訂履歴](./用語集【別紙】改訂履歴.md)）

本テーマ（`.claude/` のチーム共有・統制）の語の正本のうち、執筆とレビューで常に読む核である。核に無い語は、詳細（[用語集【別紙】詳細](./用語集【別紙】詳細.md)）を検索する。

- 新しい語は、使う前に足す
  - 2 つ以上の文書に出る語と、今後ほかの文書に出る見込みのある語を核に置く
  - 1 つの本紙とその別紙の中だけで使う略称と固有名は、用語集に載せない。その文書で初めて出す所で説明する
  - 定義には、本テーマで何を指すかを短く書く。似た語との違いは、取り違えが起きうるときだけ書く
  - ID とラベルは、付け方だけを 7 に書き、今ある番号を並べない
  - 識別子（設定のキー、起動時のフラグ、環境変数、ファイルとフォルダの名前）は載せない。使う文書の表で説明する
  - Claude Code の公式の語（plugin・skill・subagent・marketplace・managed settings・workspace trust など）は訳さず、9 で表記だけを決める
- 語を改めたら、旧い語を詳細の「改めた語」に残す
- 対象は `reports_v2.1/` の文書である。`reports/` の文書（旧い版と、まだ書き直していない文書）は、書いた時点の語のままである

「詳しくは」は、その語が指すものを詳しく書いた節である（文書は 8 の略称で書く）。

## 7. ID とラベルの付け方

`{n}` は数を表す。今ある番号の一覧と中身は、採番する文書にある。ID は参照のためだけに使い、ほかの文書で引くときは、初めて出す所に短い名前を添える（例「V7（入れ子クローンの `permissions.allow`）」）。

| 形 | 意味 | 採番する文書 |
|---|---|---|
| `案{英大文字}`（`'` や `-{n}` が付くことがある） | 配布の構成の案。採用した案は `案C-1` | 結論・構成案 §6 |
| `P{n}` | 配布設計で区別する、資産の置き場所 | 結論・構成案 §2-1 |
| `V{n}` | 未検証の項目 | 結論・構成案 §8-2 |
| `D-{n}` | 作業指示者の判断が要る事項。D-1〜D-10 は公式ドキュメント最新化レポート（2026-08-20）、D-11 以降は結論・構成案が採番する | 結論・構成案 §8-3 |
| `[{n}]` | 出典。番号は文書ごとに別で、文書をまたいで同じ番号が同じ出典を指すとは限らない | 各文書の出典一覧 |
| `{C・I・S・P}{n}` | クロスレビューの指摘（CRITICAL・IMPORTANT・SUGGESTION・POSITIVE） | 各レビュー報告書 |

`P{n}` は、レビュー報告書の中では POSITIVE の指摘を指す。置き場所の `P1`〜`P6` と取り違えないよう、レビュー報告書で置き場所を引くときは「置き場所 P1」と書く。
