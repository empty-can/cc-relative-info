## 1. 層3（managed settings）が握る統制キー

本紙 [§4-2](./結論・構成案.md#sec-4-2) の補足である。**1.1 と 1.2 のキーは managed のソースからしか読まれない** —— user や project の settings に書いても効果が無い [\[26\]](./結論・構成案【別紙】出典一覧.md#ref-26)。多くは「ロック」であり、**ロックが支配する値そのもの（permission rules や `sandbox.network.allowedDomains` 等）はどの層でも設定できるキー**で、ロックが「managed の値だけを尊重せよ」と指示する構造になっている。

> **照合の出典と手順**: managed 専用のキーの集合は、managed-settings ページの "Keys only a managed source can set" の表 [\[26\]](./結論・構成案【別紙】出典一覧.md#ref-26) を正とし、**各キーの Scope を settings-reference の索引**[\[28\]](./結論・構成案【別紙】出典一覧.md#ref-28) と突き合わせた（`BS` で 2026-11-21 に実施）。**Scope が `Managed` でないキーは managed 専用ではない**ので、[1.3](#sec-a-3) に分けてある。

<a id="sec-a-1"></a>

### 1.1 managed 専用のキー（公式が表で挙げるもの）

| キー | Scope | 効果 |
|---|---|---|
| `allowManagedPermissionRulesOnly` | Managed | permission rule の供給元を managed だけにする。**v2.1.282 以降は、リポジトリ・個人・`--add-dir`・skills ディレクトリ型の plugin に置いた skill とコマンドの `allowed-tools` も無視する**（managed の skill と組み込みの skill のものは残る。`disallowed-tools` は効く）[\[46\]](./結論・構成案【別紙】出典一覧.md#ref-46) |
| `allowManagedHooksOnly` | Managed | 走る hooks を managed 由来だけに制限。**plugin 同梱の hooks も落ちる**——例外は managed settings が `enabledPlugins` で force-enable した plugin のものだけ [\[28\]](./結論・構成案【別紙】出典一覧.md#ref-28)。v2.1.310 以降は、それ以外の plugin の monitors も止まる |
| `allowManagedMcpServersOnly` | Managed | `allowedMcpServers` を managed のものだけ尊重（`deniedMcpServers` は全ソースからマージ） |
| `allowAllClaudeAiMcps` | Managed | `managed-mcp.json` 配備時も claude.ai connectors を併用する |
| `strictKnownMarketplaces`（別名 `allowedMarketplaces`・v2.1.232+） | Managed | plugin marketplace の許可リスト。未定義＝制限なし／`[]`＝完全ロックダウン／リスト＝許可制。**v2.1.223+ で GitHub owner のワイルドカード（`"acme-corp/*"`）に対応**。**exact match は URL 正規化しない**（末尾 `/`・`.git`・`ssh://` vs `https://` は別物） |
| `blockedMarketplaces` | Managed | 拒否リスト。**ダウンロード前に判定される**ので、ブロックされたソースはファイルシステムに触れない |
| `strictPluginOnlyCustomization` | Managed | skills / agents / hooks / MCP について、**user と project に置いたものを止める**（plugin と managed 由来だけが残る）。`true` で 4 種全部、配列で個別指定。**どれか 1 種でも制限すると、skills ディレクトリ型の plugin（`@skills-dir`）はエラー無しで読み飛ばされる**[\[52\]](./結論・構成案【別紙】出典一覧.md#ref-52)。skills を制限すると、`--add-dir` のディレクトリの skills と commands、claude.ai の同期 skill も止まる |
| `disableSideloadFlags`（v2.1.193+） | Managed | `--plugin-dir` / `--plugin-url` / `--agents` / `--mcp-config` を**起動時に拒否**。環境変数 `CLAUDE_CODE_PLUGIN_DIRS`（v2.1.280+）で plugin のフォルダを渡した場合も起動時に終了し、Agent SDK の `addPlugins`（v2.1.301+）は呼び出しが失敗する。cloud セッションでは in-process `type: "sdk"` 以外の MCP を落として起動 |
| `disableCommandPluginSources`（v2.1.229+） | Managed | `command` ソースの plugin を全面禁止。marketplace の `headersHelper` コマンドも塞ぐ（v2.1.238+）。未設定時は `allowManagedHooksOnly` に追随 |
| `pluginSuggestionMarketplaces` | Managed | plugin のサジェストを許す marketplace |
| `pluginTrustMessage` | Managed | install 前の trust 警告に追記するメッセージ |
| `channelsEnabled` / `allowedChannelPlugins` | Managed | channels の可否／メッセージを push できる channel plugin の allowlist |
| `managedMcpServers`（v2.1.259+） | Managed | 全ユーザーへ配る remote MCP サーバー（ロックではなく**供給**） |
| `sandbox.filesystem.allowManagedReadPathsOnly` | Managed | `filesystem.allowRead` を managed のものだけ尊重（`denyRead` は全ソースからマージ） |
| `sandbox.network.allowManagedDomainsOnly` | Managed | `allowedDomains` と `WebFetch(domain:…)` allow を managed のものだけ尊重 |
| `forceRemoteSettingsRefresh` | Managed | 起動をブロックしてリモート managed settings を再取得。失敗したら **exit**（フェイルクローズ） |
| `policyHelper` | Managed | managed settings を起動時に**動的計算**する実行ファイル |
| `managedSourcesBehavior` | Managed | 最優先の managed ソースだけを適用するか、**全ソースを合成**するか |
| `parentSettingsBehavior` | Managed | ホスト供給の親 settings を managed policy の下にマージするか |
| `wslInheritsWindowsSettings` | Managed | WSL が Windows のポリシーチェーンを読むかどうか（HKLM か `C:\Program Files\ClaudeCode` 配下で設定した場合） |

### 1.2 公式の表に無い managed 専用のキー

公式は「表に無いキーは settings-reference の Scope の列を見よ」としている [\[26\]](./結論・構成案【別紙】出典一覧.md#ref-26)。索引で Scope が `Managed` のキーが、managed 専用である。本書に関係するものを挙げる。

| キー | 効果 | 出典 |
|---|---|---|
| `claudeMd` | managed の `CLAUDE.md` の本文を `managed-settings.json` に直接書く（別ファイルを置く代わり） | [\[17\]](./結論・構成案【別紙】出典一覧.md#ref-17) |
| `requiredMinimumVersion` / `requiredMaximumVersion` | 範囲の外の版で**起動を拒否**する（`minimumVersion` より強い） | [\[28\]](./結論・構成案【別紙】出典一覧.md#ref-28) |
| `enforceAnthropicSignIn`（v2.1.329+） | Anthropic の API での claude.ai のログイン（または Enterprise Admin Console でのサインイン）を必須にする。**managed settings のファイルか MDM のポリシーに置いたときだけ読まれ**、server-managed・HKCU・`policyHelper` の出力に書いても無視される | [\[48\]](./結論・構成案【別紙】出典一覧.md#ref-48) |

`BS` の索引では、ほかに `allowClaudeInChromeWithManagedMcp`・`allowedProviders`・`availableModelsMatch`・`deniedModels`・`disableRemotePreviewScripts`・`gatewayInternalNetworks` などが `Managed` である。配布設計に関わらないので、中身は調べていない。

### 1.3 managed でなくても設定できるが、managed に置くと統制として機能するキー

次のキーは、settings-reference の Scope が `Managed` ではない。**managed 専用ではなく**、ほかの settings にも書ける。**managed に置いた場合は上書きできなくなる**ので、統制として機能する。

| キー | Scope | 効果 | 注意 |
|---|---|---|---|
| `permissions.disableBypassPermissionsMode` | **Any file** | `--dangerously-skip-permissions` を無効化 | **project の `settings.json` に書いても、メンバーが `settings.local.json` で戻せる。** 強制したいなら managed が要る |
| `allowedHttpHookUrls` | **Any file** | HTTP hook の送信先 URL を制限 | 同上 |
| `forceLoginMethod` | **Any file** | ログイン方法（Claude アカウント / API キー等）を指定 | 同上 |
| `forceLoginOrgUUID` | **Any file** | ログインする組織を指定 | **managed 以外に書いた場合は、ログインのときに組織を先に選ぶだけで、制限にはならない**（公式の索引に "only managed settings enforce it" とある）[\[28\]](./結論・構成案【別紙】出典一覧.md#ref-28) |
| `permissions.blockWritesOutsideWorkingDirectories`（v2.1.314+） | **Any file** | 作業ディレクトリの外への書き込みを止める | どのファイルの `true` も効く。**リポジトリから有効にはできるが、メンバーが自分で有効にしたものをリポジトリから解除はできない**[\[48\]](./結論・構成案【別紙】出典一覧.md#ref-48) |
| `permissions.denyInsteadOfPrompting`（v2.1.319+） | **User or managed** | 確認を出す代わりに拒否する | **project の `settings.json` には書けない**（リポジトリからは設定できない）[\[48\]](./結論・構成案【別紙】出典一覧.md#ref-48) |
| `forceLoginGatewayUrl` | **User or managed** | ログイン先の gateway を指定 | project の `settings.json` には書けない。server-managed からは読まれない（[1.4](#sec-a-4)） |

> **なぜこの区別が要るか**: 「managed 専用」だと思い込むと、**層3 の基盤が無いチームは、これらのキーを最初から諦めてしまう**。Scope が `Any file` のキーは、チームの `settings.json` に commit すれば（上書きされうるものの）効かせられる。逆に「commit したから強制できている」と考えるのも誤りである。

> **⚠ チームが層3 を「使える」と誤認しないこと。** **1.1 と 1.2 のキーは**すべて**組織の IT 管理者が配布基盤で配るもの**であり、リポジトリに commit しても一切効かない。チームが自前で握れる統制の仕組みは、本紙 [§4-1](./結論・構成案.md#sec-4-1) の上 3 つと、この表の `Any file` のキーだけである。

### 1.4 managed のソースが複数あるときの優先順位

| 段階 | 規則 | 出典 |
|---|---|---|
| managed の層の中での選択 | 既定では **「ポリシーのキーを 1 つ以上供給した最初のソース」**を採る。server-managed を先に見て、次に endpoint-managed。選ばれなかったソースの値は、選ばれたソースがそのキーを書いていなくても使われない | [\[27\]](./結論・構成案【別紙】出典一覧.md#ref-27) |
| どのソースからも読まれるキー | 少数のキー（sandbox の allowlist のロック、`allowManagedMcpServersOnly`、`deniedMcpServers`、`disableClaudeAiConnectors`、`syncClaudeAiPlugins` など）は、選ばれなかったソースにあっても読まれる。`env` は変数ごとに、定義している最も優先度の高いソースの値が使われる。ユーザーが書き換えられる HKCU は対象外 | [\[26\]](./結論・構成案【別紙】出典一覧.md#ref-26)[\[27\]](./結論・構成案【別紙】出典一覧.md#ref-27) |
| ログイン関係のキー | 端末に MDM のポリシーか managed settings のファイルがあれば、`forceLoginOrgUUID` と `forceLoginMethod`（`"claudeai"`・`"console"`）は、server-managed にも書かれていても、**ポリシーかファイルの値が使われる**。gateway のログインのキー（`forceLoginGatewayUrl` など）は server-managed からは読まれない | [\[26\]](./結論・構成案【別紙】出典一覧.md#ref-26) |
| `policyHelper` の作用 | 選ばれたソースが MDM のポリシーか managed settings のファイルで、そこに `policyHelper` があれば、**その出力が、そのセッションの唯一の managed settings になる**（MDM・ファイル・HKCU の値は、`forceRemoteSettingsRefresh` と `enforceAnthropicSignIn` などを除いて無視される）。**server-managed がポリシーのキーを配っている間は、helper は実行されない** | [\[27\]](./結論・構成案【別紙】出典一覧.md#ref-27) |
| 全ソースの合成 | `managedSourcesBehavior` で、**全部の managed のソースを合成する**挙動に変えられる | [\[26\]](./結論・構成案【別紙】出典一覧.md#ref-26) |
| managed 優先の例外 | 13 個のキーは、**下位のスコープの「より制限的な値」が managed の値に勝つ**（`permissions.blockWritesOutsideWorkingDirectories`・`permissions.denyInsteadOfPrompting` などを含む） | [\[25\]](./結論・構成案【別紙】出典一覧.md#ref-25) |

## 2. 起動時オプションと `--add-dir` の例外ロード

> **案C-1 では、この節の仕組みをいずれも使わない。** この節は ①案A を評価・比較するため ②配布先の組織が層3 を敷いている場合の相互作用を知るため ③既存成果物からの参照（`#adddir-exceptions` 等）を維持するため に残す。

<a id="sec-b-1"></a>

### 2.1 設定と資産を渡す起動時オプション

| フラグ | 渡せるもの | 形式 | 注意 |
|---|---|---|---|
| `--add-dir <dir>` | 追加ディレクトリの skills / commands / subagents / `enabledPlugins` / `extraKnownMarketplaces`。＋環境変数併用で `CLAUDE.md`・rules（**完全な一覧は [2.2](#adddir-exceptions)**） | ディレクトリ | 層3 の `disableSideloadFlags` の**対象外** |
| `--settings <file-or-json>` | settings.json 全般（permissions / hooks / env 等）。command-line precedence で他スコープと**マージ** | ファイル or JSON | 同じく `disableSideloadFlags` の**対象外** |
| `--mcp-config <file-or-json>` | MCP サーバー定義（複数可）。`--strict-mcp-config` で当該のみに限定 | ファイル or JSON | **`disableSideloadFlags` / `managed-mcp.json` で起動不能になる**（[§4-3](./結論・構成案.md#sec-4-3)） |
| `--plugin-dir <dir/.zip>` | **plugin 一式**（skills/commands/agents/hooks/MCP/output-styles/LSP/monitors/bin/channels）。そのセッションのみ | ディレクトリ or .zip | 同上 |
| `--plugin-url <url>` | plugin `.zip`（URL から） | URL | 同上 |
| `--agents <json>` | subagent 定義（インライン JSON） | JSON 文字列 | 同上 |
| `--append-system-prompt-file <file>` | system prompt への追記テキスト | ファイル | —— |
| `--setting-sources <list>` | 使う setting source を限定する | カンマ区切り | `project` を外すと**追加ディレクトリの skills/commands/subagents が全部落ちる**[\[20\]](./結論・構成案【別紙】出典一覧.md#ref-20) |
| `--safe-mode` / `CLAUDE_CODE_SAFE_MODE=1` | （渡すのではなく）`CLAUDE.md` / skills / plugins / hooks / MCP / commands / agents / output-styles / workflows・テーマ・キーバインド・statusline・LSP・auto memory を**全て読まずに起動** | フラグ | 切り分け用。**managed settings のポリシーは適用され続けるが、managed の plugin・skill・`CLAUDE.md`・MCP サーバーは読まれない**[\[34\]](./結論・構成案【別紙】出典一覧.md#ref-34) |

> **共通の注意**: これらは原則**「そのセッションのみ」適用**で、毎起動でランチャーが付与する必要がある（恒久設定ではない）。**強制力は弱い**（ランチャー経由起動を各自任せにする以上、素の `claude` で迂回される）。`--settings` / `--mcp-config` とも **managed policy（層3）には従う**（managed の deny を緩められない）。

### 2.2 `--add-dir` の例外ロードの一覧（正本）

> `--add-dir`／`/add-dir` で追加したディレクトリの `.claude/` からロードされる資産の**正本**。各成果物の同種の早見表は運用の早見であり、**版に依存する事実が食い違った場合は本表を優先**する。

| 資産 | ロードされるか | 条件・版への依存 |
|---|:---:|---|
| `skills/`（`.claude/skills/`） | ✅ | **v2.1.165 以前から対象**。**live reload あり**。`--add-dir`／`/add-dir` 限定 [\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19)[\[8\]](./結論・構成案【別紙】出典一覧.md#ref-8) |
| `commands/`（`.claude/commands/`） | ✅ | **v2.1.235+ で追加**（それ以前は非ロード）。**live reload なし**（変更後は再起動）。追加ディレクトリとプロジェクトで同名コマンドがある場合は**プロジェクト側が優先** [\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19)[\[9\]](./結論・構成案【別紙】出典一覧.md#ref-9) |
| `agents/`（subagents・`.claude/agents/`） | ✅ | **v2.1.178+ で追加**（v2.1.165 では非ロード）。**live reload なし**（同上）[\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19)[\[9\]](./結論・構成案【別紙】出典一覧.md#ref-9) |
| `settings.json` / `settings.local.json` の `enabledPlugins` / `extraKnownMarketplaces` | △ | **この 2 キーのみ**[\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19)。**追加ディレクトリの trust を保存するまで、`extraKnownMarketplaces` は読まれない。対話の端末のセッションでは、`true` の `enabledPlugins` も読まれない**（v2.1.319 以降）[\[47\]](./結論・構成案【別紙】出典一覧.md#ref-47) |
| `CLAUDE.md` / `.claude/rules/` / `CLAUDE.local.md` | △ | **`CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` のときのみ（all-or-nothing）**。**rules は `paths` を持たないものだけ**。`CLAUDE.local.md` はさらに `local` setting source が有効であること（既定で有効）が要る [\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19)[\[13\]](./結論・構成案【別紙】出典一覧.md#ref-13) |
| `settings.json` のその他キー（**permissions / hooks / env**）・`output-styles/` | ❌ | 結合されない。物理配置か `--settings` で渡すしかない [\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19) |

**適用範囲の注意**:

- **`permissions.additionalDirectories` 設定値経由では、上記の例外は一切読まれない**（ファイルアクセスの付与のみ）[\[19\]](./結論・構成案【別紙】出典一覧.md#ref-19)
- **Agent SDK の `additionalDirectories`(TS) / `add_dirs`(Py) は上記の例外を丸ごと受ける**。SDK が各エントリを `--add-dir` として CLI へ渡すため。**TypeScript 側の名称が settings キー `permissions.additionalDirectories` と同名だが挙動は正反対**[\[20\]](./結論・構成案【別紙】出典一覧.md#ref-20)
- **これらは `project` setting source 経由でロードされる**。`--setting-sources` / `settingSources` で `project` を外すとロードされず、**bare mode は commands と subagents をスキップする（skills はロードされる）**[\[20\]](./結論・構成案【別紙】出典一覧.md#ref-20)
- **作業ディレクトリ配下のサブディレクトリ**なら、セッション途中に `/add-dir <サブディレクトリ>` で skills / commands / subagents をロードできる（追加の作業ディレクトリとしては登録されない。**v2.1.257+**）[\[21\]](./結論・構成案【別紙】出典一覧.md#ref-21)
- **trust が及んでいないフォルダを、対話の端末のセッションで `--add-dir`／`/add-dir` で足すと、trust を尋ねられる**（v2.1.326+）。ただし、**この確認に答えても trust は保存されない**。保存するには、そのディレクトリでセッションを起動して trust のダイアログを承認する [\[47\]](./結論・構成案【別紙】出典一覧.md#ref-47)
- 追加ディレクトリの skill がプロジェクトの skill と同じ名前のときは、`/<接頭辞>:<skill 名>` の形で両方使える（v2.1.309+）[\[8\]](./結論・構成案【別紙】出典一覧.md#ref-8)

### 2.3 例外ロードを絞る仕組み

| 機構 | 効き方 | 使える層 | 制約 |
|---|---|---|---|
| **共有ディレクトリの中身で絞る** | 置かないものは読まれない。**最も確実で唯一チーム主体で完結する** | 全員 | 設計・レビューの規律に依存 |
| **`claudeMdExcludes`** | `CLAUDE.md` / `rules` を**パス・glob 単位**で除外。**user / project / local / managed の全スコープで設定可・commit 可・配列はスコープ間でマージ**[\[18\]](./結論・構成案【別紙】出典一覧.md#ref-18) | **チーム（project へ commit）** | 静的。**managed policy の `CLAUDE.md` は除外できない**[\[17\]](./結論・構成案【別紙】出典一覧.md#ref-17) |
| **`--setting-sources` から `project` を外す** | フラグ追加ディレクトリの skills / commands / subagents が全部落ちる [\[20\]](./結論・構成案【別紙】出典一覧.md#ref-20) | 起動側（ランチャー） | **作業リポジトリ自身の project 設定も同時に落ちる** |
| **bare mode** | **commands と subagents をスキップ。skills はロードされる**[\[20\]](./結論・構成案【別紙】出典一覧.md#ref-20) | 起動側（headless） | 対話運用向けではない |
| **`--safe-mode`** | customization を全無効化 [\[34\]](./結論・構成案【別紙】出典一覧.md#ref-34) | 起動側 | トラブルシュート用。常用しない。managed の plugin・skill・`CLAUDE.md` も読まれなくなる |
| **`strictPluginOnlyCustomization`** | skills / agents / hooks / MCP を plugin ＋ managed 由来のみに制限 | **層3（managed）のみ**[\[28\]](./結論・構成案【別紙】出典一覧.md#ref-28) | **Scope が Managed 固定。チームレベルでは使えない** |

> **チームが主体的に握れるのは上 2 つだけ。** これは [§4-1](./結論・構成案.md#sec-4-1) の結論と同じであり、**`--add-dir` を使っても使わなくても変わらない**。案C-1 が `--add-dir` を捨てるのは統制力の差ではなく、**起動フラグ依存と `permissions` 二重化を消すため**である（[§6-2](./結論・構成案.md#sec-6-2)）。

## 3. 配布の柱から外した経路

配布経路として名前は挙がるが、**チームの配布設計の柱にはしない**ものである。「検討し忘れた」ではなく「検討した上で外した」ことを記録する。

| 経路 | 何ができるか | 柱にしない理由 |
|---|---|---|
| **claude.ai の同期 skill**（`~/.claude/skills/synced/`） | claude.ai のアカウントで有効な skill が同期される。自分で作るか有効にした skill、**組織が claude.ai で提供する skill**、Anthropic の組み込みの skill が対象。Cowork・cloud のセッションに加えて、**claude.ai のアカウントでサインインした端末のセッションでも、設定なしで同期される**（v2.1.273 以降。止めるには `syncClaudeAiSkills` を `false` にする）[\[5\]](./結論・構成案【別紙】出典一覧.md#ref-5) | **組織が skill を提供する手段と、それに要るプラン・ロールが、Claude Code の公式ドキュメントに書かれておらず、自分の組織で使えるかを確かめていない**（本紙 [§8-2](./結論・構成案.md#sec-8-2) の V10）。**運べるのは skill だけ**で、`CLAUDE.md`・`rules`・`permissions` は運べない。同期されないセッションもある（下の箇条書き） |
| **Organization settings > Plugins**（claude.ai） | 組織として plugin を配布・許可できる。claude.ai から同期される plugin（`@synced`）は、端末のセッションにも届く [\[43\]](./結論・構成案【別紙】出典一覧.md#ref-43) | **プラン依存（Team / Enterprise）で、自チームで使えるかが未確認**（本紙 [§8-2](./結論・構成案.md#sec-8-2) の V1）。使えるなら共有リポの担当範囲が狭まるので、**確認する価値はある**。`bin/` を持つ plugin は配れない（本紙 [§1-7](./結論・構成案.md#prereq-plugin)） |
| **`--plugin-dir` / `--plugin-url`** | plugin 一式をセッション単位で渡せる | 「そのセッションのみ」で恒久設定にならない。加えて層3 の `disableSideloadFlags` で**起動時に拒否されうる**（本紙 [§4-3](./結論・構成案.md#sec-4-3)）。**開発・テスト用途では必須**なので、自組織で `disableSideloadFlags` を有効化することは推奨しない |
| **`rules/` の symlink 共有** | `.claude/rules/` に共有ディレクトリを symlink する | 作業ディレクトリ外を指す symlink は**外部 import 扱い**で承認が要り、**承認後も `paths:` 付き rule はロードされない**[\[16\]](./結論・構成案【別紙】出典一覧.md#ref-16) |
| **`~/.claude/` へ配る** | 全プロジェクト共通の個人設定 | **チームが `~/.claude/` へ配る公式経路は存在しない**（各自の手作業になる） |
| **`pluginConfigs` を commit する** | plugin へ渡す設定値の配布 | **project / local settings からは読まれない**。clone したリポジトリからの値注入を防ぐ設計 [\[40\]](./結論・構成案【別紙】出典一覧.md#ref-40) |
| **`.claude/` を git submodule にする（案C-2）** | ブランチ切替はできる | 作業リポジトリ側に**submodule のピンがコミットされる**ため、`.claude/` の更新が作業リポの履歴を汚す。**gitignore した素の clone にすれば両方消える**（本紙 [§6-2](./結論・構成案.md#sec-6-2)） |

同期 skill が**同期されないセッション**[\[5\]](./結論・構成案【別紙】出典一覧.md#ref-5):

- `/login` で保存したサインインを使わないセッション（API キーでの認証、`ANTHROPIC_AUTH_TOKEN`・`CLAUDE_CODE_OAUTH_TOKEN`・`apiKeyHelper` で資格情報を渡す場合）
- feature flag を Anthropic から取得しないセッション（Amazon Bedrock、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` を設定した場合など）
- bare mode と `--safe-mode` のセッション
- managed settings が skills を plugin 由来に制限しているセッションと、`--setting-sources` から `user` を外したセッション

非対話の短い実行は、新しく加わった skill のダウンロードが終わる前に終わることがある（`CLAUDE_CODE_SYNC_SKILLS=1` で、ダウンロードを待たせられる）。
