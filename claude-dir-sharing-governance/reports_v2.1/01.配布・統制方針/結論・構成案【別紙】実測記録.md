## 1. 環境と判定の方法

| 項目 | 値 |
|---|---|
| 測った日 | 2026-11-21（表で断ったものを除く） |
| CLI | Claude Code 2.1.330 |
| git | 2.46.0.windows.1 |
| OS とシェル | Windows 11、Git Bash |
| モデル | `claude --model haiku -p`。`haiku` は Claude Haiku 5.5（`claude-haiku-5-5`）に解決された。Edit ツールの実測だけ、モデル名を指定して Claude Haiku 4.5 と 5.5 の両方で測った |

判定には、次の 2 つだけを使った。

- **合言葉の一致**: 資産ごとに固有の文字列（合言葉）を埋めておき、セッションの回答にその文字列が出るかを見る。合言葉を読みに行けないよう、先行操作に使うツールと `Skill` ツールだけを許可した
- **`Skill` ツールの起動の成否**: skill がロードされているかは、`Skill` ツールで実際に起動して、合言葉が返るかエラー（`Unknown skill`）になるかで見る

モデルの自己申告（「ロードされています」という回答）は判定に使っていない。

## 2. 実測の一覧

### 2.1 入れ子クローンからのロード（本紙 [§3-1](./結論・構成案.md#sec-3-1)）

作業リポジトリ（`.gitignore` に `.claude/`）の `.claude/` へ共有リポジトリを clone し、作業リポジトリのルートから起動した。

| 対象 | 合言葉 | 結果 |
|---|---|:---:|
| `.claude/CLAUDE.md` | `NESTCLONE-CM7701` | ロードされた |
| `.claude/rules/plain-rule.md`（`paths:` なし） | `NESTCLONE-RU7702` | ロードされた |
| `.claude/settings.json` の `env` | `NESTCLONE-EV7703` | 適用された（`printenv` で確認） |
| `.claude/skills/probeskill/SKILL.md` | `NESTCLONE-SK7704` | `Skill` ツールで起動できた |

作業リポジトリの `git status --short` は空だった。再現: `bash nestclone-setup.sh` → `bash nestclone-run.sh`

`permissions.allow` が適用されるかは、この実測では分からない（`claude -p` は workspace trust のダイアログを出さない。本紙 [§8-2](./結論・構成案.md#sec-8-2) の V7）。

同じ足場で、作業リポジトリに `git worktree add` で linked worktree を作り、そのルートから起動した。worktree に `.claude/` は作られなかった（作業リポジトリが gitignore しているため）。

| 対象 | 結果 |
|---|:---:|
| `.claude/CLAUDE.md` | ロードされなかった |
| `.claude/rules/plain-rule.md`（`paths:` なし） | ロードされなかった |
| `.claude/settings.json` の `env` | 適用されなかった |
| `.claude/skills/probeskill/SKILL.md` | `Skill` ツールで起動できた（本体の checkout から読まれた） |

再現: `bash nestclone-setup.sh` → `bash nestclone-worktree.sh`。`claude --worktree` で作る worktree と、subagent の worktree 分離は測っていない（本紙 [§8-2](./結論・構成案.md#sec-8-2) の V12）。

### 2.2 条件付きロードの発火（本紙 [§3-2](./結論・構成案.md#conditional)）

1 つのサブディレクトリ `sub/` に、`paths: ["**/*.probefile"]` の rule がマッチする対象ファイル、`sub/CLAUDE.md`、`sub/.claude/skills/subskill/` を置き、先行操作だけを変えて 1 セッションずつ起動した。

| 先行操作 | `paths:` 付き rule | サブディレクトリの `CLAUDE.md` | サブディレクトリの skills | スクリプト |
|---|:---:|:---:|:---:|---|
| なし（対照） | ❌ | ❌ | ❌ | `trigger-run.sh` |
| Read ツール | ✅ | ✅ | ✅ | 同上 |
| Bash で `cat <ファイル>` | ✅ | ✅ | ❌ | 同上 |
| Grep ツール | ❌ | ❌ | ❌ | 同上 |
| Edit ツール（Read を許可しない。Claude Haiku 4.5） | Edit が失敗 | — | — | `trigger-edit.sh` |
| Edit ツール（同上。Claude Haiku 5.5） | ✅ | ✅ | ✅ | 同上 |
| Write ツール（新規作成） | ✅ | ✅ | ✅ | `trigger-write.sh` |
| Bash で `head -1 <ファイル>` | ✅ | ✅ | ❌ | `trigger-bash-forms.sh` |
| Bash で `grep beta <ファイル>` | ✅ | ✅ | ❌ | 同上 |
| Bash で `cat <ファイル> \| head -1` | ❌ | ❌ | ❌ | 同上 |
| Bash で `cat <ファイル 1> <ファイル 2>` | ❌ | ❌ | ❌ | 同上 |

- Claude Haiku 4.5 での Edit は `File has not been read yet. Read it first before writing to it.` で失敗し、ファイルは変わらなかった
- `trigger-bash-forms.sh` は、モデルが実行したツール呼び出しも表示する。4 つの形とも、指示した 1 コマンドのほかに Bash コマンドは実行されていなかった
- `head`・`grep`・パイプ付き・複数ファイルの 4 形は 2 回ずつ測り、結果は同じだった。ほかの行は 1 回の結果である

再現: `bash trigger-setup.sh` → `bash trigger-run.sh` → `bash trigger-edit.sh` → `bash trigger-write.sh` → `bash trigger-bash-forms.sh`

サブディレクトリの skills を、条件付きロードを待たずにロードする方法:

| 方法 | 結果 | 測った日と版 | スクリプト |
|---|---|---|---|
| 起動時に `--add-dir sub` | `Skill` ツールで起動できた（対照のフラグなしでは `Unknown skill`） | 2026-11-21・CLI 2.1.330 | `trigger-adddir.sh` |
| 非対話で `/add-dir sub` を渡す | `/add-dir isn't available in this environment.` | 同上 | 同上 |
| `/reload-plugins` を実行する | サブディレクトリの skills はロードされなかった | 2026-09-14・CLI 2.1.266。今の版では測り直していない | スクリプトなし |

### 2.3 ブランチの名前と D/F コンフリクト（本紙 [§5-3](./結論・構成案.md#sec-5-3)）

`java` ブランチがある状態で `java/design` を作ると、`fatal: cannot lock ref 'refs/heads/java/design': 'refs/heads/java' exists; cannot create 'refs/heads/java/design'` で失敗した。

- `git switch -c` で踏む形: `nestclone-branch.sh`（このスクリプトは、失敗した後の手順もそのまま続けて実行し、失敗の連鎖を出力する）
- `git branch` の 2 コマンドで踏む形と、名前を変えて成功する形: `nestclone-branch2.sh`

ref が packed-refs に入っている状態での再現は測っていない。

### 2.4 `rebase.updateRefs`（本紙 [§5-4](./結論・構成案.md#sec-5-4)）

`master` → `java/_base` → `java/design` の 2 段で `master` を進め、`java/design` で `git -c rebase.updateRefs=true rebase master` を 1 回実行した（足場のブランチ名は、本紙の `main`・`java/base` に当たるものが `master`・`java/_base` である）。

| 条件 | 結果 |
|---|---|
| 中間ブランチ `java/_base` をローカルに持つクローン | `Updated the following refs with --update-refs: refs/heads/java/_base` と出て、中間ブランチも進んだ |
| 中間ブランチをローカルに持たないクローン | `Updated the following refs` の行が出ず、中間ブランチは取り残された（エラーにならない） |

再現: `bash nestclone-updaterefs.sh`（`nestclone-branch2.sh` の後に実行する）

### 2.5 メンバー側の更新（本紙 [§5-5](./結論・構成案.md#mirror)）

| 項目 | 結果 | スクリプト |
|---|---|---|
| リモートが rebase して force-push した後の `git pull --ff-only` | `fatal: Not possible to fast-forward, aborting.`・終了コード 128。手元は変わらない | `ffonly-test.sh`、`nestclone-branch2.sh`、`nestclone-updaterefs.sh` |
| `git fetch` → `git reset --hard origin/<ブランチ>` | 終了コード 0 で、リモートの先頭に一致した | 同上 |
| gitignore 済みで未追跡の `settings.local.json` | `switch` と `reset --hard` を挟んでも残った | `nestclone-branch.sh`、`nestclone-branch2.sh`、`nestclone-updaterefs.sh`（`ffonly-test.sh` は測っていない） |

### 2.6 ブランチの静かな破損（本紙 [§5-6](./結論・構成案.md#sec-5-6)）

存在しないブランチへの `git switch` を失敗させ（終了コード 128）、終了コードを見ずに `git reset --hard origin/<別のブランチ>` を続けた（終了コード 0）。現在のブランチの名前は `master` のまま、中身と先頭のコミットが別のブランチのものになった。

再現: `bash switch-fail.sh`（単独で実行できる）

## 3. 実行の順序

**足場を作るスクリプトから順に実行する。** 足場が無いまま後段のスクリプトを実行すると、`cd` が失敗する。スクリプトは `cd` の失敗で止まるようにしてあるが、止めない版では、後続の `git add -A`・`commit`・`reset --hard` がこのリポジトリ自身に対して実行された（2026-11-21 に実際に起きた）。

| 系列 | 実行順 |
|---|---|
| 入れ子クローン | `nestclone-setup.sh` → `nestclone-run.sh`・`nestclone-worktree.sh` → `nestclone-branch.sh` → `nestclone-branch2.sh` → `nestclone-updaterefs.sh` |
| 発火 | `trigger-setup.sh` → `trigger-run.sh`・`trigger-edit.sh`・`trigger-write.sh`・`trigger-bash-forms.sh`・`trigger-adddir.sh`（後ろの 5 本は順不同） |
| 単独で実行できるもの | `switch-fail.sh`、`ffonly-test.sh` |

どのスクリプトも、自分と同じディレクトリに作業用のフォルダを作る（`.gitignore` 済み）。

## 4. 判定を誤りやすい点

- **`--debug` のログには、条件付きロードが記録されない。** ログに出ないことを、ロードされていない根拠にできない
- **モデルの自己申告は当てにならない。** 検証中、対象のモデルが「skill はロードされています」と答え、ロードされた理由まで作文した（実際は skill の一覧に増えていなかった）。`Skill` ツールを実際に起動して成否を見る形に替えて、正しく判定できた
- **`/add-dir` は非対話（`claude -p`）では使えない。** 対話セッションでだけ使える
- **Git Bash は、`/` で始まる引数を Windows のパスへ書き換える。** `claude -p "/add-dir sub"` は、そのままだと `C:/Program Files/Git/add-dir sub` というプロンプトになる。`MSYS_NO_PATHCONV=1` を付けて実行する
- **出力を `tail` で切らない。** 回答の後ろにモデルの補足が付くと、合言葉の行が切れる
- **CLI の版が上がったら測り直す。** 発火の条件は版で変わってきた（本紙 [§8-1](./結論・構成案.md#sec-8-1)）。Edit ツールの結果はモデルでも変わる
