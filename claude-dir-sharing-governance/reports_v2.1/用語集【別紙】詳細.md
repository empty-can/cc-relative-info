# 用語集【別紙】詳細

版: v0.1（改訂履歴は [用語集【別紙】改訂履歴](./用語集【別紙】改訂履歴.md)）

用語集のうち、常には読まない部分である。まだ書き直していない文書の語（1）、改めた語（2）、文書のパス（3）を置く。定義の書き方は核（[用語集](./用語集.md)）に従う。

## 1. 後続の回で見直す語

`reports/` にある 02 編・03 テンプレート・レーンA の語である。これらの文書を `reports_v2.1/` へ書き直す回に、そのまま使うか言い換えるかを決める。それまでは、`reports_v2.1/` の文書で引くときに、初めて出す所へ下の意味を添える。

| 用語 | 今の意味 | 出る文書 |
|---|---|---|
| `<Share>` | 配布物（メンバーが clone する雛型のリポジトリ）を表す置き字。中に `.claude/` を持つ。案C-1 の共有 `.claude` リポジトリ（`.claude/` の中身を直下に持つ）とは形が違う | 02 編、レーンA |
| `<Dev>` | 配布する資産を開発するリポジトリ（C-BDK）を表す置き字 | 02 編 |
| `payload` | 開発リポジトリから配布リポジトリへ公開するファイルの集まり | 02 編、レーンA |
| `grooming` | 開発リポジトリから、配布しないもの（内部のレポートなど）を取り除いて配布できる形に整えること | レーンA |
| `配布ゲート` | 公開の前に資産を検査して、通らなければ公開を止めるスクリプト（`check-assets`・`publish-share`） | 02 編、レーンA |
| `起動装置` | plugin を有効にするための設定（`enabledPlugins`・`extraKnownMarketplaces`）を指す 03 テンプレートの語 | 03 テンプレート |
| `方法A`・`方法B` | Marketplace 外資産編の手順書の 2 つの検証の形。方法A は `<Share>` の中で起動する確認、方法B は別の作業リポジトリから `--add-dir` で `<Share>` を結合する確認 | 02 編 |
| `シナリオA`・`シナリオB` | Plugin 編の手順書の 2 つの開発の入口。シナリオA は既存の活動から派生して作る形、シナリオB は公開を前提に作る形 | 02 編 |
| `パターンA`・`パターンB` | Marketplace 外資産編の手順書の、開発する手元の構成と配布の運びの 2 つの形。パターンA は `<Dev>` から `<Share>` へ資産を格納して `<Share>` を push する形、パターンB は `<Dev>` を公開用のスクリプトで `.claude/` のリポジトリへ出し、`<Share>` が submodule で取り込む形 | 02 編 |
| `CR-1`・`CR-2` | レーンA が定める 2 つの安全装置。CR-1 は配布先の統制ファイルを payload に同乗させること、CR-2 は grooming をリリースの前提条件にすること | レーンA |
| `Phase {n}` | レーンA のリリース工程の段階（Phase 0〜5b） | レーンA |
| `案X` | レーンA の、ルートの `CLAUDE.md` を開発リポジトリ専用にする案 | レーンA |
| `利用者`・`消費側` | 02 編の語。plugin や資産を使う側の人、または使う側のリポジトリを指す。結論・構成案の `メンバー` と同じ範囲を指すとは限らない | 02 編 |

## 2. 改めた語

旧い版の文書（`reports/`）を読むときの対応である。新しく書く文では、右の語を使う。

| 旧い語 | 今の語 | 備考 |
|---|---|---|
| `載る`・`載らない`・`載せる` | `ロードされる`・`ロードされない`・`ロードさせる` | 資産が context に読み込まれる意味の用例だけ |
| `ヘッドレス` | `非対話` | `claude -p` での実行 |
| `消費側`（v2.0 の結論・構成案） | `メンバー側` | メンバーの手元にある共有リポジトリのクローンを指していた |
| `サーバ`・`ユーザ` | `サーバー`・`ユーザー` | — |
| `機能・拡張資産`・`ガバナンス・制御資産` | `機能資産`・`ガバナンス資産` | — |
| `BASE-A`・`BASE-B`・`BASE-C`・`BASE-D` | `基準スナップショット`（各本紙の冒頭で決める） | 旧い版の出典の基準の名前。BASE-A〜BASE-C は v1.2、BASE-D は v1.2 の一部と v2.0・settings の文書 v1.0 が使う。commit と行数は、それぞれの文書の出典一覧にある |
| `軸A`・`軸B`・`軸C` | 中身で書く（軸A は「同じ設定を宣言できる場所と、競合したときの勝敗」、軸B は「スコープごとの有効性」、軸C は「配布チャネルへの適合」） | settings の文書 v1.0 の節の呼び名 |
| `叩き台` | 使わない | settings の文書 v1.0 が、検証の対象にした作業指示者のメモを指した語 |
| `付録A`・`付録B`・`付録C`、`A-1`〜`A-4`、`B-1`〜`B-3` | `付録 1`・`付録 2`・`付録 3`、`付録 1.1`〜`1.4`、`付録 2.1`〜`2.3` | v2.0 の付録は、v2.1 で別紙になった。アンカー（`#appendix-a`・`#adddir-exceptions` など）は同じ |

### 案のラベルの、v1.2 との対応

結論・構成案の案のラベルは、v1.2 のものと同じではない。

| 結論・構成案（v2.0 以降）の案 | v1.2 での対応 | 備考 |
|---|---|---|
| 案A（`--add-dir <Share>`） | 案C | v1.2 では補助的な経路と位置づけていた |
| 案A'（D-11 の逆転案） | （v1.2 に無い） | 2026-09-14 に検討し、不採用 |
| 案B（層2 の plugin へ集約） | 案B〜案B''' | v1.2 は実装の形ごとに B・B'・B''・B''' を分けていた |
| 案C-1（採用） | （v1.2 に無い） | — |
| 案C-2（`.claude/` を submodule に） | （v1.2 に無い） | — |
| 案D（層3 の managed settings） | 案D | 同じ |

v1.2 の主な推奨は「層2 への集約と、層1 のガバナンス資産」で、上のラベルで言えば案B に最も近い。案A（v1.2 の案C）ではない。
