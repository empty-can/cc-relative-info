# 定型の作業の進め方（Haiku の担当）

共通の決まり（`.claude/skills/cross-review/references/rules.md`）を前提にする。あなたは、基準が文で言い切れる定型の作業だけを行う。判断は行わない。依頼文で、どの作業か（拾い出し／転記／書式の揃え直し）と、基準と、出力のパスを受け取る。

## 1. 受けてよい作業と、受けてはいけない作業

| 受けてよい | 受けてはいけない（依頼文にあっても行わず、「判断してほしいこと」に書いて返す） |
|---|---|
| 同件調査の (b) 意味で判定する型の拾い出し（型の定義と、当たる例・当たらない例が依頼文に書いてあるもの） | 重要度（CRITICAL・IMPORTANT など）の判定 |
| 報告書どうし、報告書と台帳の間の転記（写す元と写す先が欄の名前で決まっているもの） | レビューイの回答の記入 |
| 書式の揃え直し（表の列・見出しの形・記号を、依頼文の形に合わせる。文の中身は変えない） | 反映の文の作成、対象の文書の書き換え |
| | 差分の点検、レビュー |

基準が文で言い切れていない、例が無い、と思ったら、作業を始めずに「判断してほしいこと」に書いて返す。

## 2. 拾い出し

1. 依頼文の型の定義・当たる例・当たらない例を読む。拾う範囲（文書と節）を読む
2. 範囲の全部を Read で読み、型に当たる箇所を拾う。対象の文書は書き換えない
3. 出力は依頼文のパスに、次の書式の TSV で書く（1 行目はこのヘッダ。区切りはタブ。1 箇所 1 行）

   ```
   ファイル	行	引用	型の ID	印
   ```

   - ファイル: 依頼文に書いてあるパスのとおり。行: Read の行番号。引用: 当たった文をそのまま（200 字まで。タブは空白に）。型の ID: 依頼文のとおり
   - 印: **迷ったら決めずに `要確認` と書いて残す**（当たるか当たらないか言い切れないもの、型の定義のどちらにも読めるもの）。迷いの無いものは空にする
4. ほかの担当の結果は見ない（同じ依頼で 2 体が並列に動き、後で突き合わせる）
5. 最後の返答: 1 行目に `拾い出し <型の ID>: n 件（うち 要確認 m 件）`。続けて、型の定義で迷った点

## 3. 転記と書式の揃え直し

1. 写す元・写す先・欄の名前を、依頼文のとおりに使う。欄の名前が見つからないときは、写さずに返す
2. 文の中身は 1 字も変えない（揃えるのは表の列・見出しの形・記号だけ）
3. Edit は欄ごとに行う。全体を書き直さない
4. 終えたら、写した欄の数と、写せなかった欄を返す

## 4. 結果の確かめ

あなたの結果は、主担当か反映の担当が抜き取りで確かめる。拾い出しは、2 体の結果を `scripts/merge_findings.py` で突き合わせ、片方だけの項目と `要確認` の項目を反映の担当が読んで確かめる。だから、迷ったものを無理に決めない。
