# レビューアの進め方

共通の決まり（`.claude/skills/cross-review/references/rules.md`）を前提にする。依頼文で、どの回か（Round 1／確認の回 n 回目／構成の確認）と、固有の値を受け取る。

## 1. 自分のテンプレート

テンプレートは自分の観点の 1 本だけを Read ツールで読む。ほかの観点のテンプレートは読まない。パスはリポジトリのルートからの相対パス。

| 観点 | テンプレート | ID の接頭辞 |
|---|---|---|
| 論理整合性 | `.claude/skills/cross-review/templates/レビューア/論理整合性.md` | `C` `I` `S` `P`（例 `I3`） |
| 実用性 | `.claude/skills/cross-review/templates/レビューア/実用性.md` | `C-` `I-` `S-` `P-`（例 `I-3`） |
| 作業指示者+人間読み手 | `.claude/skills/cross-review/templates/レビューア/作業指示者+人間読み手.md` | `U-C` `U-I` `U-S` `U-P`（例 `U-I3`） |
| 構成の確認（作業指示者+人間読み手の担当だけ） | `.claude/skills/cross-review/templates/レビューア/構成の確認.md` | `K` |

## 2. Round 1（0.8 版）

1. 依頼文の対象の文書を全部読む。判断基準の文書と、扱う状態の範囲（依頼文にあるとき）を読む
2. 報告書は主担当が `python -I -X utf8 .claude/skills/cross-review/scripts/report_tool.py new` で作ってある（依頼文の報告書のパス。名前・日付・版 0.8 は記入済み）。無ければ同じスクリプトで作る（手で写さない）。残りの `{{…}}` を埋める
3. 観点ごとに指摘を出す（§4 の書き方）。依頼文の「決まっていること」は指摘の対象にしない
4. セルフレビューを行う（§5）。誤検知は落とす
5. 指摘の無いラベルは、雛型の指摘（`### C1. {{タイトル}}` など）を消し、節の見出しの下に「該当なし」と書く（題が `{{` で始まる雛型の指摘はスクリプトが数えないが、報告書に残さない）。件数表の 0.8 の列は `python -I -X utf8 .claude/skills/cross-review/scripts/report_tool.py fill-counts <報告書> 0.8` で書く（数えて書き、検算まで行う。手で数えない）。判断依頼サマリーを書く（§7。行は `report_tool.py summary <報告書>` が選ぶ。0.8 の時点では回答も確認の態度も無いので、SUGGESTION 以下を除いた C・I の全部が出る）。変更履歴に 1 行足す
6. `check_lf.py` で報告書に CR が無いことを確かめる
7. 最後の返答（§9）

## 2b. 構成の確認（執筆の前・1 回だけ。作業指示者+人間読み手の担当）

1. 依頼文の構成案と、承認する人・その人が決めることを読む
2. テンプレート `構成の確認.md` を Read で読み、依頼文の出力のパスへ Write で写す
3. 見るのは 2 つだけ: 承認する人が判断できる構成か／判断材料に過不足が無いか。文の読みやすさ・表記・事実の正しさは見ない。版・件数表・確認の回は無い
4. 判断のための文書と運用の手順書を分ける方がよいときは、その案を K-I に書く。構成の選択で、執筆の前に決めないと本文が膨らむものは「決めてほしいこと」に書く
5. セルフレビューは §5 の前半・後半を 1 回ずつでよい。最後の返答は依頼文の形

## 3. 確認の回（n 回目）

前の回と同じレビューアが再開されたときは、自分の前の回の文脈を使ってよい。新しいレビューアとして起動されたときは、報告書を引き継ぎ、前の回の指摘と「レビューア確認」の欄を全部読む。どちらでも、執筆者の回答をうのみにせず、直した後の文書を自分で読んで確かめる。

1. **前の回の指摘の解消を確かめる**（対象は依頼文が挙げる ID。無ければ、前の回で追加した指摘と、前の回で再指摘にした指摘）
   - 回答（同意の程度、同件調査の結果、反映した箇所、回答から変えた点）を読み、今の文書の該当の節を自分で読む
   - 「レビューア確認」の欄を書く（§6）。見出しの回の印は必ず「（確認 n 回目）」の形で書く（例 `##### C1. レビューア確認: 問題点（確認 2 回目）`。収束の判定のスクリプトがこの印で数える。印の無い欄があるとスクリプトは止まる）。前の回の欄があるときは消さずに、その後に足す
   - 回答が「採用」でも、直した文が誤っている・別の問題を生んだ・直し漏れがあるなら「再指摘」にし、何が残っているかを書く
   - 修正案を変えて反映したものは、変えた理由が妥当かを判断する
   - 作業指示者の裁定に回したものは、本文に選択肢と代償が事実として書かれているかを確かめる
   - 仕上げの回（依頼文で指定）では、内容が変わるために作業指示者の判断待ちへ回した指摘は、文書が直っていなくても再指摘にしない。依頼文の判断待ちの一覧に載っていることを確かめ、態度を「受容」、最終結論を「判断待ち（1.0 で作業指示者が決める）」とする
   - POSITIVE は、今の文書でも評価が成り立つかだけを確かめ、成り立たないときだけ 1 行足す
   - それより前に解消を確かめた指摘は、今回の差分が当たった節についてだけ、壊れていないかを確かめる
2. **新しい欠陥を差分に絞って探す**: `git -C <リポジトリ> diff <前の対象> <今の対象> -- <パス>` の差分と、差分が当たった節だけを、自分の観点で読む。直していない節を読み直さない。修正が生んだ欠陥（新しい文の誤り、節の間の食い違い、出典や実測と合わない文、実行できない手順、未決の事項が新しく増えたこと）を重点的に見る
   - 追加の指摘は、該当の重要度の節の末尾に、続きの ID で足し、見出しに「（追加・確認 n 回目）」を付ける。回答の欄は空のプレースホルダにしておく
3. セルフレビュー（§5）
4. **報告書の更新**: 自分の観点の報告書だけを Edit で、欄ごとに直す（全体を書き直さない）
   - 収束の判定と次の版は `python -I -X utf8 .claude/skills/cross-review/scripts/report_tool.py converge <報告書> <n>` が出す（追加の CRITICAL・IMPORTANT が 0 件、かつ CRITICAL・IMPORTANT への再指摘が 0 件なら 0.9。収束しなければ 0.8→0.81→0.82→0.83、0.83 の後は 0.9（打ち切り））。自分で判定しない。ただし作業指示者+人間読み手（仕上げの回）は版の上限が 0.81 で、0.81 の後の確認でも収束しなければ、`converge` が 0.9（打ち切り）と出す（冒頭の表の「レビュー区分」で観点を読む。0.82・0.83 の列と変更履歴の行は `-`）
   - 出た版を `python -I -X utf8 .claude/skills/cross-review/scripts/report_tool.py set-version <報告書> <版> <日付> <内容>` で書く（打ち切りのときは内容に「打ち切り（未収束: ID）」）
   - 件数表の今回の列は `python -I -X utf8 .claude/skills/cross-review/scripts/report_tool.py fill-counts <報告書> <版>` で書く。判断依頼サマリーを作り直す（§7）
   - 末尾の「確認の回の記録」の節に、n 回目の分を足す: 対象のコミット、読んだ範囲、実行したもの（足場のパスと出力）、セルフレビューの回数、落とした指摘の候補
5. `check_lf.py` で CR が無いことを確かめる。最後の返答（§9）

## 4. 指摘の書き方

- 各指摘の見出しの直下に「**観点**: <観点名>」を 1 行置く。1 件は主な観点 1 つに数える。ほかの観点にもまたがるときは、影響の大きい方を主にし、ほかは本文に注記する
- **事実認定型**（「X は誤り」「Y と食い違う」）は、典拠（文書の節と引用、公式の断面の行、実測の出力）と、誤りと認める根拠を必ず書く
- **表現改善型**（「X はあいまい」「Y は冗長」）は、直した後の具体例を修正案に必ず書く
- 推測を含むときは「推測」と書く。自信が無い指摘は、事実誤認・前提の取り違え・読み落としが無いかを確かめてから出す。確かめて妥当でないと分かったら出さない（出した指摘は根拠を持つものとして扱われる）
- 問題点は「概要・問題点・影響・詳細・根拠」に分け、番号で対応させる
- 修正案は必ず表で書く（案が 1 つでも、デメリットが無くても）。書くことの無いセルは「なし」、表の下の詳細で書くことが無ければ「無し」と書く
- 判断を仰ぐときは、推す案の先頭に「★」を付け、推す根拠のメリットと、推さない案のデメリットを太字にする
- 場所は節の番号と文の引用で示す。行番号を添えるときは `L1234@<対象コミットの短いハッシュ>` と書く
- 手順を含む文書では、依頼文の「扱う状態の範囲」を判断の基準にする。スコープ外の状態で起きることは、文書の「スコープ外」の節に書かれているかだけを見る（報告書の「スコープ外」の節（担当しない観点）とは別）
- 主要な指摘ごとに、最も強い反論が想定済みかを Devil's Advocate チェックリストに書く

## 5. セルフレビュー

前半と後半を分けて行う。

| フェーズ | 上限 | 終了条件 | 観点 |
|---|---|---|---|
| 前半（新しい NG の検出） | 5 回 | 直近の 1 回で新しい NG が 0 件。CRITICAL の候補がある間は上限なし | 各観点に新しい指摘の候補が無いか／典拠は明確か／重複・冗長な指摘が無いか |
| 後半（誤検知のチェック） | Opus 3 回／Sonnet 4 回 | 直近の 1 回で誤検知が 0 件。CRITICAL の候補が全部外れた時点で通常の上限に戻す | 事実の認定は正しいか／ラベルは適切か（CRITICAL を過大に数えていないか）／典拠に基づく反論で覆らないか |
| 確認の回の後 | 上限なし | 報告書の整合が取れたとき | 取り込んだ後の報告書の整合／取り下げ・重要度変更の根拠が明確か／件数表と確認の欄が連動しているか |

回数を「確認の回の記録」（Round 1 では変更履歴の行）に書く。

## 6. レビューア確認の欄

「レビューイからの回答（問題点）」の直下に「レビューア確認: 問題点」、「レビューイからの見解（修正案）」の直下に「レビューア確認: 修正案」を置く。SUGGESTION は 1 つの「レビューア確認」にまとめる。

| 項目 | 内容 |
|---|---|
| レビューア態度 | 受容／取り下げ／重要度変更／再指摘／修正採用 |
| 理由 | 回答に対する判断の根拠（典拠つき） |
| 最終結論 | 受容: 元の指摘で確定／取り下げ: 撤回／重要度変更: 例 IMPORTANT → SUGGESTION／再指摘: 次の版（0.81〜0.83。作業指示者+人間読み手は 0.81 まで）で Round 2 をやり直す／修正採用: 回答を踏まえた改変版で確定 |
| 収束ステータス | 達成／1ラウンド継続／議論継続 |

- 受容: 回答の完全同意・部分同意を踏まえ、元の指摘と修正案を確定する
- 取り下げ: 典拠に基づく反論で、事実誤認・前提の取り違えと分かった。件数表の「取り下げ累計」に数える
- 重要度変更: ラベルを変える。新しいラベルで現役の件数に数え、古いラベルから外す。変更履歴にも書く
- 再指摘: 回答を踏まえても問題が残る
- 修正採用: 回答の提案を踏まえた改変版を採る
- 収束ステータス: 達成＝最終の修正案が双方の合意で決まり、新しい論点が無い／1ラウンド継続＝回答の追加の案の採否に、レビューアの再検証が要る／議論継続＝認識の不一致が残る
- 態度の行の書き方: `report_tool.py` が読むのは `* **レビューア態度**: <受容・取り下げ・重要度変更・再指摘・修正採用のどれかで始まる値>` の形だけ。1 つの確認の欄に、ちょうど 1 行書く（`レビュアー態度`・`**態度**:`・`-` の箇条・全角のコロンの行は、読めずにスクリプトが止まる）。値が `{{…}}`・`（未記入）` のままの欄は未記入と読まれる
- C・I は、問題点と修正案の両方の「レビューア確認」の欄を、確認の回ごとに書く（確かめるはずの C・I に未記入の欄が残ると、`converge` が止まる）

## 7. 判断依頼サマリー

作業指示者に判断を頼む指摘を、重要度ごとの見出しで分けた表に並べる（優先度の列は置かない）。確認の回の後に、その回のレビューアが作り直す。表の行の選び出し（除外基準 1・2）は `python -I -X utf8 .claude/skills/cross-review/scripts/report_tool.py summary <報告書>` が出す。レビューアは、出た骨組みの「差し戻しリスク」の欄（`{{差し戻しリスクの概要}}`）だけを書く。行を足し引きしない

```
##### CRITICAL（{現役の件数} 件、判断依頼の対象 {表の件数} 件）
| ID | タイトル | 差し戻しリスク | 態度表明 |
```

- 除外基準 1: SUGGESTION 以下（ラベルで機械的に決める）
- 除外基準 2: レビューイが完全同意し、レビューアが受容しただけの指摘（追認だけで済む。レビューア確認の態度で決める）
- ただし、作業指示者の裁定に回した事項を含む指摘（回答の「作業指示者の裁定」が「要」「一部要」のもの、修正案の回答の「裁定に回す点」が「無し」でないもの）は、除外基準 2 に当たっても載せる
- 除外した指摘も本文の指摘の欄には残す。該当する指摘が無いラベルは、見出しを残し、表の代わりに「該当なし」と 1 行書く
- 各 ID は本文の指摘へのリンクにする

## 8. 件数表

- 重要度ごとに表を分ける（CRITICAL／IMPORTANT／SUGGESTION／POSITIVE）。行は観点、列は版（0.8・0.81・0.82・0.83・0.9・1.0）
- 各列には、その版を付けた時点の現役の件数を書く。0.8 を書く時点では、ほかの列は `<TBD>`。到達しなかった版の列は空欄、発生しない版は `-`（作業指示者+人間読み手の 0.82・0.83 の列は、いつも `-`）
- 前の列と同じ値は「同左」と書く
- 取り下げがあったら、取り下げた後の現役の件数を書き、「取り下げ累計」の行に累計を書く
- 重要度変更は、新しいラベルの表に数え、古いラベルの表から外す。表の下の注記にも書く

## 9. 最後の返答

必ずこの形で始める（Round 1 では「追加の」を「Round 1 の」と読み替え、再指摘の行は「—」）。

```
追加の CRITICAL: n 件／追加の IMPORTANT: n 件／追加の SUGGESTION: n 件
既存の CRITICAL・IMPORTANT への再指摘: n 件（ID: …）
取り下げ: n 件／重要度変更: n 件／版: 0.xx
```

続けて、追加の CRITICAL・IMPORTANT と再指摘の題を 1 行ずつ、8 行以内で。末尾に共通の決まり §5 の 3 項目。
