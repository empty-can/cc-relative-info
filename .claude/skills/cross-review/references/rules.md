# クロスレビューの共通の決まり

この決まりは、クロスレビューの全部の担当に当てはまる。依頼文と食い違う所は、依頼文を優先する。ただし §4 のコマンドの決まりは、依頼文で緩めない。

コマンドの繋ぎ方、読み取りを並べること、背景での実行、小分けに書くこと、決まりから外れた実行の報告は、起動時に足される「サブエージェントの共通の決まり」に従う（このファイルには重ねて書かない）。サブエージェントの共通の決まりより hook の方が厳しい所（§4）は、hook に従う。クロスレビューの文書で「共通の決まり §n」と書くときは、このファイルの §n を指す。

担当は、作業を始める前に、このファイルと自分の役割のファイル（`.claude/skills/cross-review/references/` の下の `reviewing.md`・`revising.md`・`diff-check.md`・`clerk.md` のどれか）を Read で全部読む。レビューアと差分の点検の担当は、自分のテンプレート 1 本も読む。読まずに始めない。

リポジトリやテーマに固有の値（作業フォルダ、対象の文書、対象のコミット、判断基準、扱う状態の範囲、決まっていること、文書の決まり、担当名）は、依頼文で受け取る。このファイルには書いていない。依頼文に無い値は推測で補わず、最後の返答の「判断してほしいこと」に書く。

## 1. 役割と版の進み方

| 役割 | 担当 |
|---|---|
| レビューア | 観点ごとに 1 体。執筆者から独立した第三者。報告書を書く |
| 反映の担当 | 執筆者（レビューイ）の側。回答、同件調査、反映、反復セルフチェック |
| 差分の点検の担当 | 反映した担当とは別の 1 体。差分だけを疑う目で見る |
| 定型の作業の担当（clerk） | 拾い出し・転記・書式の揃え直し。判断はしない（Haiku） |
| 主担当 | メインのセッション。進行、範囲の絞り込み、作業指示者への伺い |
| 作業指示者 | 人間。設計の選択と 1.0 版の判断 |

報告書の版は観点ごとに進む。

| 版 | いつ付くか |
|---|---|
| 0.8 | レビューアが Round 1 を終えたとき |
| （版は変えない） | Round 2: 反映の担当が回答・同件調査・反映を行う。差分の点検を挟む |
| 0.9 | 確認の回で、追加の CRITICAL・IMPORTANT が 0 件、かつ CRITICAL・IMPORTANT への再指摘が 0 件だったとき（収束） |
| 0.81 → 0.82 → 0.83 | 確認の回で収束しなかったとき。版を 1 つ進め、Round 2 からやり直す（主担当は台帳に記録して進む。作業指示者への報告はしない）。上限は観点で違う: 論理整合性・実用性は 0.83 まで、作業指示者+人間読み手（仕上げの回）は 0.81 まで（レビューと対応の組は最大 2 回） |
| 0.9（打ち切り） | 上限の版（2 観点は 0.83、作業指示者+人間読み手は 0.81）の後の確認の回でも収束しなかったとき。そこで反復を止め、未収束の ID を冒頭の表と変更履歴に書く。作業指示者+人間読み手では、残った指摘を段階 6 の判断待ち事項に載せる |
| 1.0 | 作業指示者が態度を表明し、その反映と差分の点検が済んだとき |

- SUGGESTION の追加と再指摘は、収束を妨げない。読みやすさ・説明の精度の項目は、収束した後の仕上げの回でまとめて扱う
- 版の表記: 未到達の版は空欄、フロー上発生しない版（スキップ）は `-`（作業指示者+人間読み手の 0.82・0.83 は、いつも `-`）

## 2. 指摘のラベルと重要度の基準

| ラベル | 意味 | 対応 |
|---|---|---|
| CRITICAL | 差し戻しになる本質的な問題、または成果物の信頼性を損なう問題 | 必ず直す |
| IMPORTANT | 本文の理解・運用に支障が出る問題 | 直すことを強く推す |
| SUGGESTION | 直さなくても運用できる改善の余地 | 任意 |
| POSITIVE | 適切な判断・良い記述 | 維持を推す |

重要度は、次の基準で付ける。回を重ねても同じ基準で付ける。収束させるために甘くしない。厳しさを足すために重箱の隅を IMPORTANT にもしない。

- **IMPORTANT 以上**: 承認・実行の判断を誤らせる／手順が実行できない・復旧しない／事実と合わない
- **SUGGESTION**: 読みやすさ・表記・説明の精度
- IMPORTANT と SUGGESTION の境目の補助: (1) 本文全体を精読しないと気づけない問題なら IMPORTANT 寄り (2) サマリ表など、本文を読まずに参照される箇所に響くなら IMPORTANT 寄り

## 3. 用語

| 用語 | 意味 |
|---|---|
| 差し戻し | 承認する人が「これでは進められない」と判断し、成果物を執筆者に戻すこと（原因） |
| 手戻り | 上流の不備のために、後の工程をやり直すこと（結果）。差し戻しは手戻りの代表的な原因 |
| 取り下げ | レビューアの指摘が、事実誤認・前提の取り違えで覆ること |
| 同件調査 | 1 件の指摘と同じ型の誤りを、文書の全体から拾う調査 |
| 確認の回 | Round 2 の反映をレビューアが確かめる回（旧称 Round 3） |
| 差分の点検 | 反映の後、レビューに回す前に、別の担当が差分を疑う工程 |
| 足場 | スクリプトを実際に動かして確かめるための、使い捨てのディレクトリ |
| スコープ内／スコープ外 | 手順を含む文書の「扱う状態の範囲」の区分。スコープ内は場面で確かめる状態、スコープ外は確かめずに、文書の「スコープ外」の節に 1 か所でまとめて書く状態 |

## 4. コマンドの決まり

クロスレビューの担当の Bash・PowerShell・Write・Edit は、担当の定義の hook（`scripts/hook_pre_bash.py`・`hook_pre_write.py`）が検査する。止まったら、その文の「直し方」に従う。同じ形でやり直さない。

### 4.1 hook が通す形

先頭の `NAME=値` の並びを外した後、次の形だけが通る。ほかの形は全部止まる。

| 形 | ツール | 使いどころ |
|---|---|---|
| `bash <ファイル> [引数…]` | Bash・PowerShell | 自分で書いたスクリプトを流す（`bash -n <ファイル>` は構文の確かめ。この 3 語の形だけ。後ろに別のオプションを付けると止まる） |
| `python -I -X utf8 <ファイル> [引数…]` | Bash・PowerShell | 自分で書いたスクリプト・skill の中のスクリプトを流す |
| `git -C <パス> <読み取りのサブコマンド> [引数…]` | Bash・PowerShell | 読み取りの git（サブコマンドは下の一覧。`--no-pager` は `-C <パス>` の前後に置いてよい） |
| `pwsh`・`powershell` `-NoProfile [-NonInteractive] [-NoLogo] [-ExecutionPolicy Bypass\|RemoteSigned] -File <ファイル> [引数…]` | PowerShell だけ | `.ps1` を流す（git・削除を含む `.ps1` は止まるので、guard つきの bash のラッパーから呼ぶ。§4.4 の 2） |

- 実行ファイルは名前だけで書く。パスつき（`/mingw64/bin/git`・`C:/Python/python.exe`・`<フォルダ>/bash`）は止まる
- 先頭の `NAME=値`（`VERIF_ROOT=…` など）は、Bash ツールの `bash`・`python` の形の前だけに付けてよい。`git` の前には付けない。止まる名前: `BASH_ENV`・`ENV`・`SHELLOPTS`・`BASHOPTS`・`PATH`・`LD_PRELOAD`・`PROMPT_COMMAND`・`PYTHONSTARTUP`、`GIT_*`・`BASH_FUNC_*`・`CROSS_REVIEW_*`（テスト用の口）・`CLAUDE_*`
- 改行・`;`・`&&`・`||`・`|`・`&`・ヒアドキュメント・`$(…)`・バッククォート・リダイレクト（`>` `<`）を含むコマンドは、**引用符の中でも**止まる（`git log --format="%h;%s"` は `--format=%h%x3b%s` に替えるか、スクリプトに書く。`|` は `%x7c`）
- Bash ツールのコマンドは、bash と同じ引用符の解き方で読む（`"cherry"-pick` は `cherry-pick`、`"--out"put=` は `--output=` と読む）。`git` の形は、`$`（変数・`$'…'`・`${…}`）と波括弧の展開（`{a,b}`・`{a..b}`）を含むと止まる（`HEAD@{1}` は通る。`git grep 'foo$'` のように `$` が要る読み取りは、Grep ツールかスクリプトで行う）
- PowerShell ツールでは、括弧 `(` `)` `{` `}` を含むコマンドも止まる（`Program Files (x86)` のようなパスも。スクリプトに書く）
- `ls`・`cat`・`grep`・`echo`・`rm`・`Remove-Item`・`env`・`source`・`claude`・`git clone` などは、通す形に無いので止まる。読むだけなら Read・Grep・Glob ツールを使う。複数の処理・絞り込み・削除は、Write ツールで `<作業フォルダ>\30_tmp\<担当名>\` に `.sh` か `.py` を書いて、上の形で流す
- 背景の実行（`run_in_background: true`）: ファイルを流す形（`bash`・`python`・`-File`）は、§4.2 の走査を通れば背景でも通る。`git -C` の読み取りは背景では止まる（前面で流す）。背景で流してよい場合と待ち方は、サブエージェントの共通の決まりに従う

読み取りの git のサブコマンド（サブコマンドの前に置けるのは `-C <パス>`（1 つ）と `--no-pager` だけ。`-c`・`--exec-path`・`--git-dir`・`-P` などは止まる。`-C` の無い `git clone …` なども止まる）:

- 後ろに何を続けてもよい: `diff`・`show`・`log`・`status`・`ls-files`・`ls-tree`・`rev-parse`・`cat-file`・`blame`・`grep`・`shortlog`・`describe`・`merge-base`・`rev-list`・`show-ref`・`for-each-ref`・`name-rev`・`cherry`・`diff-tree`・`diff-index`・`diff-files`・`count-objects`・`check-ignore`・`check-attr`・`whatchanged`・`range-diff`・`annotate`・`var`・`version`、2 語の `worktree list`・`stash list`・`stash show`・`reflog show`・`remote get-url`
- 決まった形だけ: `tag --list`・`tag -l`（後ろにパターンを 9 個まで）、`config --get <キー> [<値のパターン>]`・`config --get-regexp <キーのパターン> [<値のパターン>]`、`remote -v`・`config --list`・`config -l`（後ろに何も付けない）
- `branch` の一覧: 後ろが一覧のオプション（`-a`・`--all`・`-r`・`--remotes`・`-v`・`-vv`・`--verbose`・`--list`・`-l`・`--show-current`・`--no-color`・`--no-column`・`--omit-empty`、値を取る `--contains`・`--no-contains`・`--merged`・`--no-merged`・`--points-at`・`--sort`・`--format`）だけなら通る。パターン（オプションでない語）は `--list`・`-l` があるときだけ（`branch -a foo` は止まる）
- 引数なし: `branch`・`tag`・`reflog`・`remote`
- サブコマンドの後ろに付けると止まるオプション: `--output`・`--ext-diff`・`--open-files-in-pager`・`--exec`・`--upload-pack`・`--receive-pack` と、その 4 字以上の略記（`--op=`・`--outp=`・`--ext` など。git は一意な略記を受ける）、`-O`、`git grep` の短いオプションの束ねの中の `O`（`-lO<命令>`。`-e` などの値の中は除く）。`ls-files -o`・`--output-indicator-new`・`--no-ext-diff`・`--exclude-standard` は通る

### 4.2 流すスクリプトの中身で止まるもの

`bash`・`python`・`-File` で流すファイルは、hook が中身を読む（拡張子によらない。読めなければ止まる。skill の `scripts/` の下の固定のスクリプトは読まずに通す）。次のものは止まる。

- 書き込み系の git か削除（`rm`・`rmdir`・`find -delete`・`shutil.rmtree`・`from shutil import rmtree` の後の `rmtree(…)`・`import shutil as X` の後の `X.rmtree(…)`・`os.remove`・`os.system`・`os.popen`・`subprocess` で呼ぶ `rm`・`Remove-Item`・`Remove-Item(…)`・`[System.IO.Directory]::Delete(…)` など）があるのに、それより前で guard を読み込んでいないもの（§4.4 の 1）。guard とみなすのは §4.4 の 1 の形だけ（bash は `source`・`.` の後のパスが**絶対パス**で skill の `guard_tmp.sh` そのもの。Python は同じ呼び出しに `run_name="guard_tmp_run"` がある `runpy.run_path`）。相対パス・変数のパス・別の場所の `guard_tmp.sh`・`run_name` の無い形は guard とみなさない（bash は無いファイルの `source` で止まらず、`run_name` が無いと guard は何もしない）
- **別のスクリプトを流す行**（`bash`・`sh`・`source`・`.`・`python`・`pwsh -File`、PowerShell の `& <スクリプト>`、Python の `["bash", …]`・`["python", …]`・`[sys.executable, …]`・`subprocess`・`os.system` の文字列の `bash …`・`runpy.run_path`）: 流す先が字句の絶対パス（相対パスは、スクリプトが場所を移す前に限り、流したときの場所から）で読めれば、その中身も同じ走査にかける（3 段まで。循環は 1 回だけ読む）。呼ぶ行より前に guard があれば、呼ばれる側は guard を読み込んだものとして読む。流す先に書き込み系の git か削除があるか、中身を読み取れない（変数・式・無いファイル・4 段目）ときは、その行も guard が要る行に数える。読むだけのスクリプトから読むだけのスクリプトを呼ぶ形、自分で guard を読み込むスクリプトを呼ぶ形は、guard なしで通る
- 対象のリポジトリの絶対パスへの書き込み系の git・削除と、リポジトリへ `cd` した後の書き込み・削除（作業フォルダの `30_tmp` の下は除く。ただし同じ行に別のリポジトリのパスがあれば止まる。`git clone` は元のパスだけを除く）
- 書き込み系の git の `-C`・`--git-dir`・`--work-tree`・Python の `cwd=` に、変数・式（f 文字列・`format` の `{…}` を含む）・`..` を含むパス・`C:\tmp` の外の絶対パスを書いたもの（guard があっても止まる。足場の中の git は、足場からの相対パスで `-C`・`cwd=` を付けずに書く）。Python の配列の形の git は、1 要素 1 行に書いても読む
- guard の後で、足場の外へ移りうる場所の移動（`cd -`・`cd`（引数なし）・`cd ~`・`popd`（guard の後の `pushd` で積んでいないもの）・`cd "$変数"`・`os.chdir(<変数>)`・guard の場所より上へ出る `..`・`C:\tmp` の外の絶対パス）の後の書き込み系の git・削除。足場の中の下の階層へ移って `cd ..` で戻る形、guard の後の `pushd <下のフォルダ>` と `popd`、`C:\tmp` の下の絶対パスへの `cd` は通る
- guard の後の削除の対象に、`C:\tmp` と作業フォルダの `30_tmp` の外の絶対パスか `..` を書いたもの（guard は今の場所しか確かめない）
- `scaffold.py clean`（大文字小文字・引用符で割った形を含む）・`CROSS_REVIEW_*`・`cross-review-hook.`（hook の設定・ログ）を含むもの
- 読むだけの照合は通る（Python の配列の形の読み取りの git `["git", "-C", REPO, "show", …]` も通る）。コメントとみなすのは行の頭が `#` の行だけなので、行の途中の `# …` の語も読まれる。文字列・docstring・`grep` の引数の「git commit」「rm -rf」も書き込み・削除と読まれる。読むだけのスクリプトなら、その語を分けて書く（`git-commit`・`rm-rf` のように空白を外す）
- 走査は近似である（変数の中身・リダイレクト・呼ばれる側のスクリプトの中の `cd` は見ない）。hook を通ったことを安全の根拠にせず、§4.4 を守る

### 4.3 書き込み先

- Write・Edit は `hook_pre_write.py` が絞る。止まるもの: 一時の場所（`/tmp`・`%TEMP%`・`AppData/Local/Temp`・scratchpad）、hook の設定の allow で担当の種類ごとに許された場所の外、hook の設定 `.claude/workspace/cross-review-hook.json`・ログ `<作業フォルダ>\30_tmp\cross-review-hook.log`・名前が `cross-review-hook.` で始まるファイル。パスは `..` を解いてから照らす
- Write・Edit の後に CR が入ると知らされる（直すのは担当）
- hook の設定が無い・壊れている・雛型のままのときは、担当の Bash・PowerShell・Write・Edit が全部止まる。設定は主担当が段階 0 で置く。担当は設定に触れず、最後の返答の「判断してほしいこと」に書いて返す

### 4.4 hook では止められないので、文で守るもの

1. **足場**: 足場は `python -I -X utf8 .claude/skills/cross-review/scripts/scaffold.py make <名前>` で `C:\tmp\<名前>` に作り、終わったら `scaffold.py remove <名前>`（下の階層のパスも可）で消す。`scaffold.py clean` は主担当だけが使う。**足場を使うスクリプトは、冒頭で足場へ移ってから `guard_tmp` を読み込む**。検査は足場の外なら終了コード 3 でスクリプトごと止める。足場の中では、足場からの相対パスで書く（絶対パスで外を指す操作は、検査も hook もすり抜ける）
   - bash（`<リポジトリ>` は絶対パスで書く。`C:/…` か `/c/…`。変数・相対パスにしない）:
     ```
     VERIF_ROOT=C:/tmp/<名前>
     cd "$VERIF_ROOT" || exit 3
     source "<リポジトリ>/.claude/skills/cross-review/scripts/guard_tmp.sh" || exit 3
     ```
   - Python（`run_name="guard_tmp_run"` を省かない。省くと guard は何もしない）:
     ```
     import os, runpy
     os.chdir(r"C:\tmp\<名前>")
     runpy.run_path(r"<リポジトリ>/.claude/skills/cross-review/scripts/guard_tmp.py", run_name="guard_tmp_run")
     ```
   - guard の後は、足場の中の下の階層へだけ移る（`cd <下のフォルダ>`・`cd ..` で戻る）。`cd -`・`popd`・`cd "$変数"`・`os.chdir(<変数>)` で元の場所へ戻らない。片付けも足場の中で、足場からの相対パスで行う
2. スクリプトの中の git（足場の中の git）と削除は、1 の形のスクリプトの中でだけ行う
   - 対象の文書が持つ検証スクリプト（git や削除を含み、`guard_tmp` を読み込まないもの）や `.ps1` を流すときは、1 の形のラッパー（足場へ移り guard_tmp を読み込んでから、その検証スクリプトを `bash` か `pwsh -NoProfile -File` で呼ぶ .sh）を書いて、ラッパーを流す。直接流すと hook が止める。呼ぶ先は字句の絶対パスで書く（hook が呼ぶ先の中身も読む。§4.2）
   - hook が呼ぶ先を読んで通しても、呼ばれる側がどこで動くかは呼ばれる側の書き方による（`$(dirname "$0")` から場所を決めるスクリプトは、ラッパーが足場にいても自分の置き場所で動く）。hook を通ったことを、足場で動く根拠にしない
3. 一括置換は Python のバイトモードで行う（テキストモードは LF を CRLF に変える）。CR を確かめるときは `python -I -X utf8 .claude/skills/cross-review/scripts/check_lf.py <ファイル>...`（終了コード 0 なら CR なし、1 なら CR あり）
4. 公式の仕様は、依頼文で渡された公式ドキュメントの断面の該当の行を自分で読んで確かめる。確かめられないものは「推測」「未確認」と書き、断定しない

`.claude/skills/…` のパスは、リポジトリのルートからの相対パスである。見つからないときは Glob ツールで `**/cross-review/scripts/check_lf.py` を探す。

## 5. 報告の決まり

- 最後の返答は、依頼文と自分の役割のファイルが決めた形で始める
- 最後の返答の末尾に、次の 3 つを必ず書く。無ければ「無し」と書く
  - **最初に読んだファイル**: 作業を始める前に Read で読んだ決まりとテンプレートのパスの一覧（このファイル、自分の役割のファイル、テンプレート）。再開されたときは「前の回に読んだ」と書き、読み直したものがあれば足す
  - **決まりから外れた実行**: §4 とサブエージェントの共通の決まりから外れて実行したもの（コマンドの全文と理由）と、hook に止められたもの（何が当たったか・どう直したか）
  - **許可されなかった呼び出し**: 許可されずに実行できなかったツール呼び出し（ツール名・引数・その後どうしたか）
- 推測と実測を分けて書く。足場で流したものは、足場のパスと出力のファイルを書く
- 迷ったら、直さずに・決めずに、「判断してほしいこと」に書く
