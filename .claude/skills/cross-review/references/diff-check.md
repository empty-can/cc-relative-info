# 差分の点検の進め方

共通の決まり（`.claude/skills/cross-review/references/rules.md`）を前提にする。あなたは反映した担当ではない。直した文が正しいと仮定せず、壊れている所を探す役である。**対象の文書とレビュー報告書は編集しない。**

## 1. 入力（依頼文で受け取る）

- 差分の範囲: `git -C <リポジトリ> diff <起点> <終点> -- <パス>`、または作業ツリーと起点の差。点検の 2 回目以降は、前の点検の後に直した分だけ
- 反映の担当の報告（何を直したか、何を直さなかったか）
- 判断基準・扱う状態の範囲・決定の台帳・文書の決まり
- 点検の種類: 通常（Round 2 の反映の後）／仕上げ（内容を変えない直しの後）

## 2. 見ること

差分の 1 か所ごとに、次の 5 つを見る。仕上げの点検では 6 も見る。

1. **食い違い**: 変わった文と食い違うほかの節。変わった文の事項の名前で、対象の文書の全体を Grep する（差分の外も探す）
2. **書いた対処で本当に通るか**: 止まったときの対処・手順は、字面どおりに行うと最後まで届くか。足場で流せるものは流す（`C:\tmp\<足場の名前>`。依頼文の `verification` などを写して使う）
3. **【実測】の根拠**: 【実測】の根拠の場面（場面の ID と出力）が、文に書いた順・状態と同じか。測った順と文の順が違えば指摘する
4. **読み手に残る道**: 止まった読み手に、害の無い次の手が書いてあるか
5. **新しい未決**: 差分が、未決の事項・選択肢・「作業指示者が決める」を新しく作っていないか。決定の台帳と食い違っていないか
6. **意味が変わっていないか**（仕上げの点検だけ）: 直す前と後で、事実・条件・数・推奨・未決の事項・手順の順序が同じか。反映の担当が書いた「内容を変えていない理由」が成り立つか

差分に当たらない節の、前からあった問題は、差分の直しが言い切りにした・表に出したときだけ扱う。

## 3. 重要度

共通の決まり §2 の基準で付ける。ID は次の形にする。

- `D-I{n}`: IMPORTANT 相当（レビューに回せば IMPORTANT 以上と判定されるもの）
- `D-S{n}`: SUGGESTION 相当
- `D-U{n}`: 未確認（確かめる手が無かったもの。何を確かめれば決まるかを書く）

## 4. 出力

報告は依頼文のパス（例 `<作業フォルダ>\11_interim-artifacts\差分の点検_<版>_<回>.md`）に、テンプレート `.claude/skills/cross-review/templates/点検/差分の点検.md` の形で書く。各指摘に、在りか・今の文・何が起きるか・典拠・直し方の案（直した後の文）を必ず書く。直し方の案は、新しい未決・新しい節・足場で流していない【実測】を足さない形にする。

最後の返答は次の形で始める。

```
差分の点検: D-I n 件／D-S n 件／D-U n 件（点検の種類: 通常|仕上げ、回: n）
```

続けて D-I の題を 1 行ずつ。足場を作ったときは、消したことを書く。末尾に共通の決まり §5 の 3 項目。
