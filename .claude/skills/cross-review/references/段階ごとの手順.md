# 段階ごとの手順（主担当用）

SKILL.md の「段階」の表の詳細。その段階に入る時に、該当の節だけを読む。スクリプトは `python -I -X utf8 .claude/skills/cross-review/scripts/<名前>` で流す（以下では名前だけ書く）。進行用のテンプレートは `templates/進行/` にある。【S】はスクリプト、【H】は Haiku の担当、【判】は判断の要る手順。依頼文の雛型の欄は `{{名前。説明}}` の形で、`fill_request.py` の `名前=値` の引数で埋まる（例 `回答する報告書=`・`型の定義=`・`差分のパス=`）。`【手】` の印の欄（観点・種類で書くか消すかが変わる行、表の行）は、出力された依頼文を手で直す。

## 段階 0 準備

1. 【S】`ledger.py init <台帳> 作業フォルダ=… リポジトリ=… 対象の文書=… 報告書の置き場所=… 公式ドキュメントの断面=… 判断基準=… 扱う状態の範囲=… 文書の決まり=…`
2. 【判→S】`templates/進行/hook設定.json` の二重の波括弧の欄を全部埋め（担当ごとに書いてよい場所を決める）、リポジトリの `.claude/workspace/cross-review-hook.json`（未追跡の固定のパス）に Write する。設定が無い・JSON が壊れている・`{{` が残る・work_folder／repo／allow の型が違うと、クロスレビューの担当の Bash・PowerShell・Write・Edit が全部止まる。ログは `<作業フォルダ>\30_tmp\cross-review-hook.log` に足される。並行で別のクロスレビューを回すときは、設定が 1 つしか置けないことに注意する
3. 【S】`check_permissions.py .claude/agents .claude/settings.json .claude/settings.local.json --ledger <台帳>`。終了コード 1（決まった呼び出しが deny・ask に当たる）なら【判】`agent-permission-runtime.md` §1.3 で対処を決め、`ledger.py decide` で書く。2（引数の誤り）・3（settings が壊れている・台帳に権限の表が無い）なら、直してから流し直す。無い `settings.local.json` は誤りにならない（表の注記に「無かった」と出る）
4. 【判】対象の文書が手順（プログラムと運用手順）を含むときは、**書く前に扱う状態の範囲を決める**。`templates/進行/状態の範囲.md` で軸（例: メンテナーの人数、マージの種類、ブランチの種類、古いクローンの有無）ごとに「スコープ内／スコープ外」を表にし、⏸ 作業指示者と合意する。スコープ外は、文書の「スコープ外」の節に 1 か所でまとめて書く。手順はスクリプトと「場面 → 期待する結果」の表を正にし、文書はそれを指す。【実測】には場面の ID を添える
5. 【判】判断のための文書と、運用の手順書は分ける（既定）。分けないときは、理由を添えて ⏸ 作業指示者の合意を得る
6. 【S】`ledger.py stage <台帳> "1 構成の確認" "…"`

## 段階 1 構成の確認（執筆の前・1 回）

1. 【S】`fill_request.py <台帳> 構成の確認 <依頼文> 担当名=k1-reader 足場の名前=k1-reader 対象の文書=… 今の対象=… 日付=<YYYY-MM-DD>`。承認する人（`誰か=`）とその人が決めること（`一覧=`）は、【判】で決めて引数で渡すか、埋まらなかった欄に書く
2. `cross-review-reader-reviewer` を 1 体起動する。【S】`ledger.py agent …`
3. 【判】K-I のうち構成の選択に当たるものを、⏸ 作業指示者に伺う。決まったら【S】`ledger.py decide …`。執筆は、この skill の外で行う。対象のコミットができたら段階 2 へ

## 段階 2 Round 1

1. 【S】観点ごとに `report_tool.py new <観点> <報告書の置き場所> <日付> <対象の文書> <コミット>` で報告書を作る（名前・日付・版 0.8 はスクリプトが付ける）
2. 【S】`fill_request.py <台帳> Round1 <依頼文> 担当名=r1-logic 足場の名前=r1-logic 観点=論理整合性 報告書=… 今の対象=…`（実用性も同じ）。スコープ外の観点は `スコープ外の観点=` で渡すか【判】で埋める。`【手】` の印の行は、その観点の行だけを残して書き、ほかの行は消す
3. 2 体を 1 つのメッセージで並列に起動する。完了の通知を 2 つとも待つ
4. 【S】担当ごとに、返答を Write して `check_return.py`、`report_tool.py check-counts <報告書> 0.8`、`ledger.py agent`・`ledger.py version <観点> 0.8 <コミット> <残る C・I>`。コミットする

## 段階 3 Round 2

1. **回答**: 【S】`fill_request.py <台帳> 回答 …` →【判】`cross-review-reviser` を 1 体起動する。返ってきた「同件調査が要る型」「裁定が要る事項」を、主担当が報告書の該当の欄で読む
2. **⏸ 裁定**:【判】裁定が要る事項を、判断の割り込みの形で作業指示者に伺う。決まったら【S】`ledger.py decide`。決まらないまま進める事項は、手順・例・表をどの側で書くかを決めて台帳に書く
3. **同件調査**: 型ごとに、まず【判】型を 2 つに分ける
   - **(a) 文字列・正規表現で言い切れる型**: 【S】`grep_type.py <型の ID> <正規表現> <30_tmp\同件調査_<型>.tsv> <文書>…`。Haiku を使わない
   - **(b) 意味で判定する型**: 【H】`fill_request.py <台帳> 同件調査_拾い出し …` で依頼文を 1 本作り（`型の定義=`・`当たる例=`・`当たらない例=`・`拾う範囲=` は【判】で決めて渡す）、**同じ依頼文で `cross-review-clerk` を 2 体、並列に**起動する（依頼文は同じ。起動の prompt に「あなたは A」「あなたは B」と書き、出力を `…_A.tsv`・`…_B.tsv` に分ける）。2 体は読むだけで文書を直さないので並列でよい（「反映は 1 体」の決まりとは別）。互いの結果は見せない。続けて【S】`merge_findings.py <A.tsv> <B.tsv> <30_tmp\同件調査_<型>_突き合わせ.md>`
   - **確かめ**: 【判】片方だけの項目と `要確認` の項目を、`cross-review-reviser`（opus）が該当の文を読んで確かめる（`fill_request.py <台帳> 同件調査_確かめ …` で依頼文を作る）。食い違いの割合が高いときは、型の定義があいまいだという合図として、主担当が型を書き直して (b) をやり直すか、型ごと reviser に回す（境目の割合は、最初の実施で数字を見て決める）
   - 型ごとに、最後に reviser が「直す必要がある／あいまい／当たらない／仕上げの回へ」に分けて件数を出す。この段では直さない
4. **範囲の絞り込み**: 【判】同件調査の結果を読み、反映する範囲を決める（CRITICAL・IMPORTANT の直しと、その同じ型の「直す必要がある」項目だけ）。「仕上げの回へ」は【S】`ledger.py carry` で持ち越しに入れる
5. **反映**: 【S】`fill_request.py <台帳> 反映 …` →【判】反映する範囲の表を埋め、`cross-review-reviser` を 1 体起動する。範囲が大きいときは章ごとに分けて直列に起動する
6. **差分の点検**: 【S】`fill_request.py <台帳> 差分の点検 …` → `cross-review-diff-checker` を 1 体起動する（反映した担当とは別の新しい 1 体）
7. 【判】点検の D-I（と、主担当が選んだ D-S）を、反映の担当に直させ、直した分だけを、もう一度点検に回す。D-I が 0 になるまで繰り返す。3 回で 0 にならないときは、⏸ 作業指示者に報告する
8. 【S】報告書ごとに `report_tool.py extract` で回答の欄の埋まりを見て、`ledger.py log`。コミットする

## 段階 4 確認の回

1. 【S】`fill_request.py <台帳> 確認の回 <依頼文> 観点=… n=… 版=… 前の対象=… 今の対象=… 報告書=… 確かめる指摘=…`。確かめる指摘は【S】`report_tool.py targets <報告書> <n>` の出力の ID の並びを渡す。変わった所（`変わった所=`）は反映の報告から【判】で埋める
2. 台帳の ID に SendMessage で再開する。2 観点は並列でよい。再開できない観点は新しい担当を起動する
3. 【S】`report_tool.py converge <報告書> <n>`（終了コード 0 = 収束、1 = 未収束。次の版を出す）と `report_tool.py check-counts <報告書> <版>`。レビューアの返答の先頭 3 行と食い違えば、報告書の欄を見直させる
4. 収束した観点: 版 0.9。収束しない観点: 次の版（0.81〜0.83）で段階 3 からやり直す。作業指示者への報告はせず、止まらずに進む。そのとき【S】`diff_size.py <リポジトリ> <前> <今> <パス>` を流し、【S】`ledger.py log` で台帳に書く: 「<観点>: 追加の I n 件・再指摘 n 件。今回の差分は <diff_size の 1 行目>。次の回は <絞り方（【判】）> で進める」
5. 0.83 の後の確認の回でも収束しない観点は打ち切る（`converge` が「打ち切り」と出す）。コミットし、⏸ 作業指示者に、残る CRITICAL・IMPORTANT と、選択肢（直して差分だけを確かめる／直してレビューに回さない／既知の欠陥として残す）を報告する
6. 【S】`ledger.py version`・`ledger.py stage`。2 観点とも収束か打ち切りになったら段階 5 へ

## 段階 5 仕上げ（作業指示者+人間読み手の観点）

1. 【S】`report_tool.py new 作業指示者+人間読み手 …` と `fill_request.py … Round1 …`（判断基準に用語集・文書の方針を入れる）→ `cross-review-reader-reviewer` を起動する。0.8 版ができる
2. 反映の範囲 = この観点の CRITICAL・IMPORTANT ＋ 台帳の持ち越しの一覧。**条件は「内容を変えない」**。`fill_request.py … 反映 …`（種類は仕上げ）で `cross-review-reviser` を起動する
3. `fill_request.py … 差分の点検 …`（仕上げ）で点検する（意味が変わっていないかを含む）
4. 確認の回は段階 4 と同じ。依頼文に「仕上げの回である」と、判断待ちへ回した指摘の一覧を書く。**ただし版の上限は 0.81**（レビューと対応の組は最大 2 回）: 1 回目の確認で収束しなければ、版を 0.81 にして 2〜4（反映・点検・確認）をもう 1 回だけ行う。2 回目の確認でも収束しなければ打ち切る。`converge` は報告書の冒頭の表の「レビュー区分」でこの観点を読み、0.81 の後の未収束を 0.9（打ち切り）と出すので、`report_tool.py set-version <報告書> 0.9 <日付> "打ち切り（未収束: <ID>）"` で 0.9 にする。0.82・0.83 の列と変更履歴の行は `-`。コミットし、残った CRITICAL・IMPORTANT は段階 6 の判断待ち事項の「反映していない既知の欠陥」に載せて、段階 6 の ⏸ で判断を仰ぐ
5. 内容が変わる直しとして回されたものは、【S】`ledger.py carry … "変わる（判断待ちへ）"` で持ち越しに書き、段階 6 の判断待ち事項に入れる

## 段階 6 判断（1.0）

1. 【H】全部の報告書の判断依頼サマリーと、台帳の決定・未決を、`templates/進行/作業指示者判断待ち事項.md` から `<報告書の置き場所>\作業指示者判断待ち事項.md` へ転記させる（`cross-review-clerk` 1 体。転記の元と先の欄の名前を依頼文に書く）。【判】冒頭のクロスレビューの状態・選択肢・代償・推奨は主担当が書き、転記の結果を抜き取りで確かめる
2. ⏸ 作業指示者に判断を仰ぐ。作業指示者が自分の指摘を書くときは、`templates/進行/作業指示者レビュー.md` を写して渡す
3. 態度表明を、`fill_request.py … 反映 …`（種類は 1.0 の反映）で反映させ、差分の点検を挟む
4. 「差戻し」の指摘があれば、その指摘だけを範囲にして、段階 3 と段階 4（その観点の確認の回を 1 回）を行い、⏸ もう一度判断を仰ぐ。版は 0.9 のまま進める
5. 【S】全部の指摘に態度が付き、反映と点検が済んだら、`report_tool.py set-version <報告書> 1.0 <日付> <内容>` と `check-counts <報告書> 1.0`。コミットする。全部の担当が終わったら `scaffold.py clean`
