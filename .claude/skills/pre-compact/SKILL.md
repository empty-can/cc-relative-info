# pre-compact（コンパクション前事前準備）

`/compact` または `/clear` 実行前に呼び出し、次セッション再開時に最低限の文脈が復元できる状態を整える Skill。継続情報を memory ファイルへ外部化したうえで、会話要約を残す `/compact` と、ファイルのみで再開する `/clear` のどちらで終了するかを判定・準備する。

## 出力方針

**作業指示者の判断を要する情報と、最終的な終了方式の提示（推奨方式＋選択肢、`/compact` 選択時はコメント案）のみを出力する。** ステップ 1・3 は完全 silent。ステップ 2 は未コミット変更がある場合のみ出力する。コンテキスト消費を抑えるための方針。

**silent ステップでの禁止事項**: 「サイレントで実行中」「ステップ N を処理中」「メモリを確認しています」等の進捗説明・確認メッセージ・実行状況報告を含め、**いかなるテキストも出力してはならない**。完全無言で処理する。

## 実行手順

以下を順番に実施する。

### 1. メモリ最新化（silent）

auto-memory（`memory/` ディレクトリ）配下のメモリファイルを確認し、現在の会話で変化した情報を更新する。**出力しない**。確認観点:

- 進行中のタスクの最新ステータス・中断箇所
- 次セッション再開時の継続ポイント
- 作業指示者との合意事項で未記録のもの
- 保留中の判断事項

### 2. 未コミット変更の確認

`git status` で未コミット変更を確認する。

- **変更なし**: 出力しない
- **変更あり**: コミットメッセージ案と対象ファイルを提示し、作業指示者の判断を仰ぐ（この場合のみ出力する）

### 3. 継続ポイントの収集（silent）

次セッション再開時に必要な情報をステップ 4 の入力として収集する。**出力しない**:

- 現在実施中のタスクと中断箇所
- 保留中の判断事項（作業指示者が決める必要があるもの）
- 次セッションの最初のアクション

### 4. 終了方式の判定と準備（/compact または /clear）

ステップ 1〜3 で継続情報を memory ファイルへ外部化済みであることを前提に、終了方式を判定して準備する。

#### 4.1 方式判定

以下の条件で推奨方式を決定する:

- **`/clear` 推奨**: 次アクションが具体的に確定しており、かつステップ 1〜3 で継続情報を memory ファイルに落とし切れている。会話履歴を破棄してもファイルだけで再開できる場合。コンテキスト消費が最小。
- **`/compact` 推奨**: シリアライズしにくい暗黙知（探索的設計の判断経緯・デバッグの試行錯誤の軌跡・却下した選択肢の理由など）が次の手がかりとして必要で、ファイルに落とし切れない場合。会話要約を新コンテキストに残す。

判定が曖昧な場合は両条件への適合度を 1〜2 文で述べ、推奨を一方に決めた上で、両方を選択肢として提示する。最終決定は作業指示者が行う。

> 補足: `/clear` でもルート/.claude CLAUDE.md・MEMORY.md・ツールスキーマ・MCP instructions 等の固定ベースラインは再ロードされる。`/clear` の節約効果は実質「会話要約＋直近メッセージ分」であり、ゼロにはならない。

#### 4.2 `/compact` を推奨/選択する場合

`/compact <指示>` に渡すコメントを生成して提示する。

**コメントの書き方（公式ドキュメントに基づく指針）**:

公式例: `/compact Focus on the API changes`

- **短く・焦点を絞る**: コンパクターは intent（意図）を解釈するため、詳細なタスクリストより端的な保存指示が有効
- **「Preserve X」「Focus on Y」フレーミング**: 「現在の作業文脈と次アクションに集中して」のように意図を伝える
- **ファイルパスや手順の羅列は避ける**: コンパクターが会話から自動抽出するため冗長になる

**セルフチェックリスト**（コメント案を出力する前に必ず確認する）:

- [ ] コメントが概ね 200 文字以下か（公式例 `Focus on the API changes` から大きく逸脱していないか）
- [ ] 「Preserve X」「Focus on Y」フレーミングを使っているか
- [ ] ファイルパス・指摘 ID（C1 / I1 等）・手順の具体的羅列を避けているか
- [ ] intent（次アクション + 保持すべき方針のメタ指示）に集中しているか

いずれかに不適合があれば、コメントを修正してから提示する。

**盛り込む観点**（優先順位順）:
1. 現在進行中のタスク（最も優先）
2. 未完了の残ステップの概要
3. 保留中の判断事項（あれば）
4. 未コミット変更（あれば）

**出力形式**（作業指示者がそのままコピーして使えるよう提示）:

```
【/compact コメント提案】
/compact <生成した指示コメント>
```

#### 4.3 `/clear` を推奨/選択する場合

`/clear` は会話を完全破棄し、再開は memory ファイルのみに依存する。再開の起点は `MEMORY.md` の索引行（フック＝各行の `—` 以降の説明文）であるため、以下を順に実施する:

1. Read tool で `MEMORY.md` を読み、今回の継続タスクに対応する索引行のフックを確認する。
2. そのフックが次の 3 要素を**すべて**含むか判定する: (a) タスクが未完了・進行中である旨、(b) 再開時の最初のアクション、(c) 該当 memory ファイルを読む指示。1 つでも欠ける場合は Edit tool でフック行を更新し、3 要素を含む現在形の文にする。
3. 「`/clear` 実行後は `MEMORY.md` のフック行を起点に該当 memory ファイルを読んで再開する」旨を作業指示者に伝える。

> `/clear` 後はフックが唯一の再開キーになる。フックは過去の達成サマリではなく「次に何をするか」を指す現在形の文にする。再開時は当該 memory ファイルのみを読み、無関係な大型ファイルを無闇に読み直さない。

## 完了確認

ステップ 4 の出力後、選択された方式に応じて作業指示者に伝える:

- `/compact` 選択時: 「上記コメントを使って `/compact` を実行してください」
- `/clear` 選択時: 「`MEMORY.md` のフックを再開キーとして整えました。`/clear` を実行してください」

## /compact コメントに関する公式情報

参照元: `research-for-local-RAG-for-cc/resources/references/claude-code-llms-full.txt`（約 4667 行〜）

> For more control, run `/compact <instructions>`, like `/compact Focus on the API changes`

> Customize compaction behavior in CLAUDE.md with instructions like `"When compacting, always preserve the full list of modified files and any test commands"` to ensure critical context survives summarization

コメントは自由記述でコンパクターが intent を解釈して処理する。常時保持したい保存指示は CLAUDE.md に書く方法もある。

## 設計背景

`/compact` は built-in コマンドであり `PreCompact` hook で前処理を挟む方法があるが、hook は Claude のコンテキスト外（シェル/別 LLM 呼び出し）で動作するため、現在の会話コンテキストを踏まえた Claude 自身による能動的な準備は実行できない。詳細は `references/decision-flow.md` §2.1 参照。
