> Claude Code からの質問・提案は `skill-cc-response.md` に記入されます。

---

## 1. 背景・解決したい課題

> 現在どんな問題・不便があるか。

Claude Code 関連の公式ドキュメントの `llms.txt`、`llms-full.txt`、`claude_code_docs_map.md`をワンクリックで更新できるスクリプトが完成し、最新ファイルの更新の定期的な取得はほぼ完成した。  

しかし、これらのドキュメントの更新頻度が非常に高く（1～3に更新されるペース）、現状、以下の課題がある。

* 毎回 Claude Code にサマライズを依頼する作業がルーティン化しており、毎度手動で依頼するオーバヘッドが無視できなくなっている
* 更新差分が非常に大きいこともあり、都度サマライズのフォーマットが異なると頭に入りづらい。
* コピペすれば知人や同僚にそのまま渡せるようなサマリが更新と同時に生成されていると便利。

> なぜ Skill が必要か。

Claude Code が自律的に実行することもでき、かつ作業指示者側でもコマンドという形で実行できる柔軟な運用が可能なため。

---

## 2. ユースケース

> いつ、誰が、どういう状況でこの Skill を使うか。具体的なシナリオを 1〜3 件。

* Claude Code:
  * 自律的実行: hooks等の仕組みで作業指示者からの明示的な指示無しに本Skillを実行する。
  * 作業指示者からの指示で実行: 作業指示者による本Skillのコマンド実行に応じる形で本Skillを実行する。
* 作業指示者: llms.txt等の取得が完全にタスク化されるまでのClaude Codeへのサマライズ指示としてや、突発的な要件から再生成したいタイミングなど。

## 6. 前提事項・依存関係

> 利用する MCP・ツール・外部サービス・環境変数など。
> 「既存プラグインがあれば取得・有効化でよい」場合はその旨を記載。

- 前提: 入力となるドキュメントの最新化（＝直前に`dl_llms.sh`の実行）が完了していること。且つ、前回サマリドキュメントを公開してから、入力ドキュメント側で差分が１つでも発生していること（全く発生していなければサマリファイルも更新する必要が無いため、その時点で処理を止めてよい）
